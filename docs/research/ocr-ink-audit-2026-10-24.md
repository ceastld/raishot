# OCR 框高审查（2026-10-24）

本页记录该日期的代码审查与研究方案，历史观察不代表后续源码已经验证。开发入口是仓库内的 [OCR 实现](../../src/ppocr/)和[框与段落专题](../references/ocr-boxes-and-paragraphs-2026-10-24.md)，不需要访问其它工程。

本记录只读审查 Rust 与本机参考实现，未改生产代码、未跑 cargo、未运行真实模型。以下源码位置以本次查看为准。

## 首要结论：已有收紧没有进入主要选字路径

- `src/ppocr/pipeline.rs::finish_recognition` 最终调用 `ink_bounds::tighten`，该函数只修改 `RecognizedWord.geometry`；`word.rect`、`regions`、`line.rect`、`line.geometry`、正文和 CTC 字素证据保持。
- `src/pin_text_selection.rs::sampled_cells`（约 737 行）优先使用 `sampling.source_geometry()`，所有字素共用完整裁行高度；随后 `continuous_line_cells`（约 818 行）按相邻字素中心的中点重新分配横向范围，首尾贴满整行。
- 旧词框回退分支即使先消费了 `word.geometry`，在约 239–247 行又用 `line.geometry` 调 `continuous_line_cells`，也回到原行高。
- `src/ppocr/grapheme_ink_consumer_tests.rs` 约 139 行明确断言“墨迹收紧不改变选字几何”，前后 `marking_quads` 必须相等。所以仅调整 `ink_bounds` 阈值，通常不会改善用户目前看到的字选框高度。
- 不能直接替换 `line.geometry` 来接入：`GraphemeSampling::validated_bands` 会核对完整来源几何；修改后会使实际发射证据失效，选字回退。

## 当前收紧的门槛

`src/ppocr/ink_bounds.rs` 的做法是“在原词投影法向上对称收紧”，明确保留阅读轴和所有中线停点。

| 检查 | 当前要求 | 对普通截图的影响 |
|---|---|---|
| 文字类型 | 纯 ASCII 字母数字或 CJK；每个扩展字素恰好一个码点 | 标点、带撇号/连字符的英文词、组合重音、emoji 均不收紧 |
| 单词面积/数量 | 单 ROI ≤65,536 像素，累计 ≤2,000,000，词数 ≤4,096，行数 ≤1,000 | 超累计预算整批不收紧 |
| 图像 | ≤32M 像素，完整合法 RGB，词与行来源结构完全一致 | 较大整屏图像可能整体跳过 |
| 邻域 | 完整 halo 及外侧像素可用，边缘至少留约 2 像素 | 紧裁图或贴边字跳过 |
| 背景 | ROI 最外圈每个通道与左上角背景相差 ≤1 | JPEG、渐变、纹理、控件线条、邻字很容易跳过 |
| 非背景像素 | 只要有一个像素各通道差都小于 2 即跳过；所有偏差同极性 | 一档 AA、噪声、等亮度异色字及多色字常跳过 |
| CTC 词带 | 所有非背景像素的完整像素单元严格在词四边形内 | CTC 是发射带不是字形，常有笔画跨边界，中文单字词尤其容易不满足 |
| 主体 | 每个按字数均分的 u 槽至少 4 个平均 RGB 差 ≥40 的像素 | 淡字、分布不均英文、细体可能跳过 |
| 行带 | 法向 64 桶占用必须连续 | `i/j` 的点、重音、数字/汉字离散横画会造成空行，合法文字也可能拒绝 |
| 外形 | 32×32 主体占用网格不能像空心边框 | 防控件边框，亦可能误拒“口/回/囗”等稀疏框形汉字 |
| 收紧 | 两侧较小余白×0.8，每侧至多原高 35%；每侧至少原高 2.5% | 偏心检测框只能按较少一侧余白收紧，另一侧继续大 |
| 复核 | 重建 f32 四角后逐像素单元覆盖；所有原字素中线停点偏移 ≤0.001 | 很保守，保证不以几何误差切掉可见像素 |

其中像素覆盖、预算、取消和来源完整性检查有价值，不应为提高收紧率一起移除。最先要修的是消费路径；放宽像素判定需要单独的字形掩码证据。

## 历史整行收紧方案与适用边界

历史研究观察过一种按整行运行的收紧方案。下面仅保留其算法假设供比较，不把外部源码作为开发必读材料；当前实现以 [ink_bounds.rs](../../src/ppocr/ink_bounds.rs) 为准：

1. 在框内取亮度 32 桶众数估背景；对比阈值为 `clamp(255-inkMax,18,48)`，默认 `inkMax=220`。
2. 同时构建深字、浅字候选；抑制靠边且覆盖≥70%的横框线；按选中行带统计列投影，避免横线污染所有列。
3. 行阈值峰值×3%、列阈值峰值×4%，均至少 1；桥接原高 20%、限制在 2–8 像素的法向小间隙，允许点和主体分离。
4. 候选依据密度 1.5%–82%、长宽比≥0.45、横纵偏心≤0.72、不能同时几乎占满两轴来筛选；双方可信时备用极性分数须高 15% 才换。
5. 横向沿墨迹并加 padding（实际普通调用为 3px）；纵向保留 `max(墨迹高+2px, 原框高×0.60)`，以墨迹中心为中心，框内夹取。近轴≤4°转轴对齐，大倾角保留定向四边形。

这种整行统一行高符合当前连续选区需求，比逐字各自墨迹高更稳定。但“众数一定是背景”“弱像素是噪声”“框中心附近是目标文字”仍是启发式，彩色等亮度文字、复杂背景、误检框/邻行可能破坏假设；不得仅凭历史测试通过就整体搬回当前实现。

## 建议优先验证的一项改动

在不改变 `GraphemeSampling` 来源、字素阅读轴位置和中线停点的前提下，引入独立的**整行选区法向收紧**：原图上整行共同证明的 v0/v1 作为显示/标记几何，所有字共用这一高度；CTC 原行几何继续只供采样与来源校验。第一版可保持对称收紧来确保 caret 中线不移；不必同时尝试横向裁字。

验证分两层：先用已知 detector 四角与独立 mask 验证候选不切可见字形，再让 Tiny/Small 真模型对同一输入生成自身检测框，比较 `SelectionText` 输出实际 quads 的覆盖率与高度。要同时记录未触发数量，否则“零漏字但完全不收紧”会虚假通过。留一组独立样例不参与阈值调整；实际截图需要手工标 mask，尤其是首尾标点、i/j、上下标、边框/下划线、暗色 AA、相邻行。

本轮审查未测完整模型、当前 GUI 或旧实现门禁结果，也未确认用户报告具体截图；以上属于代码证据与待验证方案。
