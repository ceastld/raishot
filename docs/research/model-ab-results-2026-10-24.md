# 公式与离线翻译本机 A/B 结果

日期：2026-10-24（用户时区）。本次已实际下载四个模型，在本机推理并保留输入、逐例输出、速度、内存、盲评和公式排版验证。表格保留现有方案，没有改产品代码或依赖清单。

后续路线：用户将本地模型保留为候选，优先评估API。最新结果见[DeepSeek API实测](deepseek-api-results-2026-10-24.md)；下文推荐只表示本地候选内部选择，不是当前默认接入路线。

## 明确推荐

**本地候选内部选择：公式 TexTeller3 INT8；离线翻译 Index-Translate-2B Q4_K_M。两种能力按需下载，用完释放，日常截图不加载模型。**

- **公式选 TexTeller 是为了减少修正。** 全部36图正确35张，PP-FormulaNet_plus-S为29张；独立28个基式分别28/28和22/28，中文混排为4/4和0/4。TexTeller多约86 MB，已加载后的单图中位耗时多约2.24秒，但本轮正确结果明显更多，内存没有明显增加。
- **离线翻译选 Index 是质量优先的取舍。** 主集可直接使用29/32，Hy为28/32；平均语义分相同，不能说Index普遍显著更准。不过Index的主集关键错误更少，长段代码保护更稳，足以支持本项目先选它。代价为多约179 MB、短段中位慢约0.30秒。Hy是更省空间、更快的替代候选。
- 不建议首版同时让用户下载四套模型。PP-FormulaNet可留作未来纯打印公式“快速模式”候选，Hy可留作资源优先候选；先把推荐的两套接好，完成可核对、可修正的结果流程。

推荐两个模型文件合计约 **1.632 GB**；加本次完整官方 llama.cpp CPU解压包62.44 MB，为约 **1.694 GB**。这是模型和该运行时的磁盘规模，未计应用、已有OCR/ORT、未来Rust接线代码，不能当作已打包安装器的最终大小。公式可共享现有ORT；翻译另需原生GGUF运行组件。

公式36张来自28个原创基式及8个暗色/小字/模糊/重采样变体，原图用XeLaTeX生成，覆盖常规、矩阵、多行、中文和复杂式。**这是真实模型推理测试，但图像是合成的，不是自然拍照/扫描集，也没有手写。**

翻译主集32条，以中英和软件技术文本为主，另含4条涉及日语；补充4条304–894字符长段，单列，不混入主集分布。主集先Hy→Index，补充集反过来Index→Hy。

质量采用预先写定规则的**AI匿名评审**，每条X/Y随机，评审者不读模型映射；根代理复核主要差错。参考译法不是唯一正确答案。公式72份输出还逐一用XeLaTeX -no-shell-escape编译，区分“能排版”和“内容正确”。没有真人评审或统计显著性试验。

PP本次测的是231,878,904 bytes的ONNX加2,140,014 bytes分词器，和前期调研中约260 MB的Paddle原生tar不是同一种产物。Tex为INT8 encoder、merged decoder及其分词器/配置，总319,569,957 bytes。两者都不需要在本次本地环境安装Torch/Paddle。

典型差错已经复核：

- PP的f11在cases外又增加左花括号，语法能编译但画面出现双括号；f27破坏同余条件。中文f17–f20及灰底v07有乱码、无关宏、等号/条件丢失。
- Tex的唯一失败为暗色矩阵v03：部分列分隔符变成空白，3×3结构错误；同一基式的明亮图f09正确。因此深色矩阵仍必须提供原图核对。
- PP有些错误结果能编译，不能仅以EOS正常或LaTeX语法成功判断识别正确。f23/f24的额外粗体按预注册当作样式差异，没有误计语义失败。

上述结论来自真实输入与识别结果的 LaTeX 编译对照；历史实验图未随仓库发布，不能用本页替代逐例复核。

### 公式测试的重要限制

Python模块导入另耗12.41/11.63秒，受当前内存压力与环境影响，已单列，不把它算成未来Rust模型加载速度。本次未实现Rust接线，不能保证移植后恰好等于这组时间。

Tex的Pillow bicubic预处理是对上游torchvision流程的移植，并非逐像素一致；没有用参考答案调参。手写、整页混排、自然扫描、更多字体和GPU未测，35/36不是通用准确率承诺。

首轮PP测试发现每token重复查询词表大小的脚本开销；已缓存、完整重测。修复前后36张原始输出逐字相同。首轮保留作诊断，未混入正式速度数据。

## 离线翻译：效果、速度、内存、体积

“可直接使用”指语义评分至少3/4且没有关键语义、结构或代码损坏；不是译文字符串等于参考答案。

| 主集32条 | Hy-MT2-1.8B Q4_K_M | Index-Translate-2B Q4_K_M |
| --- | ---: | ---: |
| 可直接使用 | 28/32，87.5% | **29/32，90.6%** |
| 平均语义分，0–4 | 3.625 | 3.625 |
| 平均流畅分，0–4 | **3.656** | 3.531 |
| 关键错误条数 | 2 | **1** |
| 结构检查通过 | 32/32 | 32/32 |
| 无空输出/无截断 | 32/32 | 32/32 |
| 可见首字p50 / p95 | **0.694 / 0.883秒** | 0.861 / 1.089秒 |
| 完整结果p50 / p95 | **1.834 / 3.141秒** | 2.138 / 3.600秒 |
| 新进程→ready，一次观测 | 2.270秒 | 2.119秒 |
| 短句首次 / warm完整结果 | 0.501 / 0.476秒 | 0.690 / 0.667秒 |
| GGUF模型文件 | **1,133.08 MB** | 1,312.16 MB |
| 峰值物理工作集 | 1.943 GiB | 1.933 GiB |
| 采样峰值私有提交 | 0.945 GiB | 0.957 GiB |

内存两者接近。模型文件由mmap驻留的部分也属于物理工作集，但不等于私有提交，两列不可相加。公式的工作集同样受系统内存压力裁剪，不能把0.63 GiB解释成任何机器上都只需这么多内存。

主集差错不是空泛的流畅度偏好：

- Hy在t06把“旧请求回执不得覆盖新选区”翻成禁止用新选区覆盖旧回执，方向反了；t10把mouse capture译成mouse pointer。
- Index在t22丢失“少于所需空间”的定量关系，把阈值写成剩余量，也需要修正。
- 两者都在人化软件worker、下载完成数/总数提示上出错。两者均把单位s译成“秒”；这条按语义正确，只在严格字串保护上失败，没有因此扣语义分。

### 长段补充集

| 样本 | 内容 | Hy首字 / 完整 | Index首字 / 完整 |
| --- | --- | ---: | ---: |
| s01 | 英→中，识别生命周期与技术约束 | 2.466 / 10.360秒 | 2.217 / 9.815秒 |
| s02 | 中→英，离线流程、数字与取消状态 | 2.716 / 14.925秒 | 2.935 / 16.244秒 |
| s03 | 英→中，否定、条件与发布沟通 | 2.411 / 8.182秒 | 2.632 / 9.676秒 |
| s04 | 英→中，代码/公式/URL/TSV/占位符 | 2.589 / 10.357秒 | 2.815 / 13.042秒 |

两者均自然stop；最大实际输入237、输出254 tokens，未触及ctx2048或输出768上限。长段都能产出完整结果，但**完整不等于无需修正**：各2/4可直接使用。两者都有unload→uninstall、下载数/总数关系不清的问题；Hy还把完整代码片段retry_count = 3拆成标识符加自然语言说明，数值意思仍在，但违反原样保留代码的合同。Index保留了该代码。

长段平均语义/流畅分Hy为2.50/2.75，Index为2.75/3.00；结构均4/4，清单内保护项Hy3/4、Index4/4。此集只有四条，单独报告，不把它与主集简单拼成同分布总体准确率。

两者都保留了s04的4个真实Tab、8个换行及第二个空单元格。表头和行名允许翻译；这不代表已经做过Excel/WPS真实粘贴测试。

因此本轮选择Index为质量优先的默认离线包，认可Hy在速度、磁盘和部分流畅度上的优势。1条主集可用率差距不足以证明普遍优胜；这里是结合关键错误、代码保持、可选模型规模作出的明确工程取舍。

## 接入建议与未验范围

1. 先只接TexTeller3 INT8与Index 2B Q4，按需下载，不在截图启动路径加载，不同时常驻。
2. 公式先展示原图、排版预览与可编辑LaTeX；暗色矩阵、中文和多行保留人工核对入口。识别成功不能自动等同正确。
3. 翻译先保护代码、公式、URL、占位符，再核对返回；仅在提示词写“保留格式”不足以保证原样。提供术语表、原文对照、单段重试和流式反馈。
4. 对长段预计有约8–16秒的本机等待，优先让已有段落可读，完成后能修正；不把离线包默认变成首装负担。

本轮没有修改截图、表格、翻译产品功能或安装设置，没有运行cargo、编译项目Release、调用云识别/付费API。模型缓存与脚本保留，推理进程均已退出。

未验：实际Rust/GPUI接线、真实界面、Word可编辑公式、自然图片/手写、其他设备、低端CPU、GPU及长期连续运行。固定四线程、用户持续用机、单次顺序测试，结果用于这轮选型，不作为性能SLA。
