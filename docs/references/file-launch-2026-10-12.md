# 文件与贴图参数入口

长期计划中的参数化调用先接三个真实入口：直接打开图片贴图、直接打开图片编辑器，以及图片／纯文本剪贴板贴图。三个程序同目录；运行和依赖下载均不要求启动宿主。CLI 与 GPUI 工作进程两次检查完整参数，使用原生 Command 参数数组，不把文件路径拼成 shell 命令。

| 调用 | 行为 |
| --- | --- |
| `rabshot-cli --pin-file "图片路径"` | 使用已有后台文件解码和 PinView 窗口，不弹文件选择框 |
| `rabshot-cli --edit-file "图片路径"` | 使用已有图片编辑器和后台解码，可继续原位 OCR／标注 |
| `rabshot-cli --pin-clipboard` | 使用已有图片或矢量纯文本贴图入口 |
| 两个贴图入口加 `--at "x,y"` | 有符号屏幕物理像素位置；省略使用鼠标位置；沿现有工作区规则保持窗口可见 |

缺少路径、无效／重复坐标、混用入口和额外参数均拒绝，不进入默认截图。CLI 与工作进程都先确认路径是文件，后台解码失败沿原错误退出；不自动保存，不修改原图片。托盘原有裸 `rabshot-gpui --pin-file` 保持图片选择对话框，CLI 的裸同参数视为缺少路径。
