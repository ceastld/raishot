# OCR 框选多选与结果筛选

已从[交互原型](../design/ocr-result-filter.html)接入截图与图片编辑器的原生 OCR 面板，支持行集合选择和可恢复筛选。原型仍使用演示数据；生产决策由 Rust 分类器计算，CLI 额外输出建议与初版对照，原始正文和识别框保持。贴图宿主本轮仍沿用原有选字，不宣称已有行集合筛选。

## 选择与复制

- 选字与整行多选并存，不设模式切换：在文字上按下拖动是逐字选取，从空白处按下拖框则以识别行框为单位，与框相交即选整行。两种选择互斥生效，开始一种即清除另一种；原图与列表同步显示。默认页签仍为段落页。
- 普通拖框替换当前所选；Ctrl 或 Shift 拖框追加（已有选字时以其涉及的行为起点）；Alt 拖框减选，和 Ctrl 同时按下时 Alt 优先；已有整行多选时，在文字上按 Ctrl／Alt 也走拖框。列表行普通单击选中该行文字、双击复制并关闭；Ctrl 点击切换该行、Alt 点击移出整行多选。修饰键以按下鼠标时为准，Ctrl／Shift／Alt 点击空白保留原选，普通空白点击清空选择。
- “复制所选”按原始识别结果的顺序拼接各行，可选不连续内容，不带入中间未选中的文字。没有选择时为“复制保留项”。
- “排除所选”隐藏结果项，并以局部填充抹去原图上的这些行（见 [OCR 排除后填充原图](ocr-exclude-fill-2026-10-23.md)），不删除识别原始数据；Delete 可触发，Ctrl+Z 一次撤销排除／恢复及其填充。筛选弹层打开时 Esc 先收起弹层；否则取消正在拖动的框并还原拖动前选择，再否则清空选择。
- 查看已过滤项、逐项恢复后保留原有框选；重新识别、来源图像或结果版本变化时，全部临时筛选／选择状态作废。
- 原型为方便连续体验，复制后保留界面并显示内容预览。实装时沿用现有规则：截图面板按钮复制成功后关闭截图，Ctrl+C 复制后保留；贴图不关窗口。排除／恢复始终保留当前 OCR 会话。

## 自动过滤

底栏用一个筛选图标按钮打开向上展开的弹层，自动过滤启用时按钮使用强调色。顶部不再常驻已过滤数量、过滤开关与拖框提示；弹层内提供“自动过滤”开关（默认关闭）、排除所选（有选择时）、撤销（可用时）、已过滤数量、逐项恢复／恢复全部及拖框提示，不显示算法解释、分数或调参滑块。展开不改变主列表、当前页签和选择；Esc、点击外部或切页收起弹层，筛选弹层与更多菜单互斥。

“已过滤 N”统一列出自动过滤和手动排除，可逐项恢复或全部恢复。复核时原型使用虚线框，原生界面使用淡橙色带定位，色带不进入原图像素。手动恢复优先于自动判断，在本次识别中再次开关过滤不会重新隐藏；关闭过滤只恢复自动项，保留手动排除。

识别置信度不是文本相关度，也不是可直接展示的正确率。官方结果定义区分检测框分数 `dt_scores` 和文字识别分数 `rec_scores`，后者可用于阈值过滤，见 [PaddleOCR 官方文档](https://www.paddleocr.ai/main/version3.x/pipeline_usage/OCR.html)。据此推论，低分可能提示部分误识别，但小字／模糊正文也可能低分，无关的真实文字和部分误识别仍可能高分。因此，识别质量、字符结构、图像与版面上下文只作为待测试的候选特征，不以单一置信度决定去留。

当前 `contextual-symbol-v2` 根据开发集手工调整，是按图片局部统计自适应的保守启发式，未训练机器学习模型。它只读取现有文字和几何，不使用单一置信度：

- 至少三行相邻、对齐的连贯正文作为局部参照，取最近至多五行的字高与平均字宽中位数，避免远处大标题支配局部小字。
- 图形列须至少三个不同的近方形单字符，大小接近、纵向邻接且横向对齐，整列远离正文；其字高中位数至少为局部正文的 1.2 倍，字宽至少为正文平均字宽的 1.8 倍，列外缺少邻近文字支持。
- 全数字列、编号、顺序字母、非拉丁单字、短词、同尺度文字、旋转／竖排／RTL、缺失或错配几何均保留。初版的孤立小型纯图形规则作为独立基线保留。
- 超过 2048 行或 1 MiB 正文、原文与行列表不一致时全部保留；图形列候选最多 128 项、每列最多 12 项，限制组合搜索工作量。

测试集先按绘图语义标注，分成八个开发场景和八个留出场景；同图变体不跨集合。开发阶段只查看开发集，策略冻结后一次评估留出集。样本为程序绘制后实际运行 OCR 的合成截图，并非真实用户截图。OCR 未识别的装饰不计为过滤成功，合并歧义与未匹配项单列；主要关注真实文字误删与已识别杂项的过滤率。

## 数据与边界

- `src/recognition.rs` 的 `RecognizedLine`／`RecognizedWord` 当前不带分数；`src/ppocr/pipeline.rs` 已在内部丢弃空文字和识别分数低于 0.5 的行。前端开关不能恢复这些已丢弃候选；若以后要做更宽范围恢复，需要额外保留候选，不能把 UI 恢复声称为重新找回所有检测结果。
- 数据层需保留评测所需的可选质量证据及其来源；识别分数与检测分数不能混用。具体新增哪些字段随候选特征验证结果确定；没有分数的识别提供者使用 `None`，不能当作 0 分过滤。
- 保留原始 `RecognizedText` 与结果身份，独立保存所选集合、手动排除集合、手动恢复集合和算法判断。分类器输出可复核建议，不改写正文或破坏字素／定位范围。像素与额外质量证据留待更广泛真实截图评测后扩展。
- 连续选字继续使用原来的字节范围；行集合复制使用独立 `ResultSelection`，不能用命中项的最小／最大范围包住中间全文。排序沿识别结果，不按框选方向重新排序。
- 原图与导出像素保持；框选几何在完整画布坐标中处理，截图 ROI 只做既有坐标投影。表格／译文与筛选的联动另定，本原型仅覆盖逐行原文结果。

## 验证

原型的指针、复制、恢复、空状态、窄屏与主题交互已用无窗口浏览器验证，复制检查没有修改用户剪贴板。`cargo check --lib --bins`、`cargo build --bins` 通过；`cargo test --lib -- ocr_result filter_host inline_copy panel_click_host` 实际 72 项通过，覆盖分类器、增量选择、宿主坐标／取消／UTF-8 复制及原有发布／点击保护。只使用主工作区 Dev。

测试工具为 `Tools/ocr-filter-corpus.py` 与 `Tools/evaluate-ocr-filter.py`，场景定义和预标注在 `tests/data/ocr-filter/scenes.json`；PNG、原始 OCR JSON 与对照报告输出至 `output/ocr-filter/`。评测需要当前 Dev CLI，留出评估须显式记录已冻结策略。真实原生窗口、多屏／DPI 手势和真实用户截图尚未验证。

### 首轮实际 OCR 评测

16 个独立合成场景，共 161 个预标注区域。开发集在新 Dev CLI 下实际产生 79 行，留出产生 75 行；留出只在冻结后运行一次，汇总报告由缓存合并，没有重复推理或按留出调参。

| 集合 | 真实文字误删 | 已识别杂项命中 | 杂项漏过 | 初版命中 |
| --- | --- | --- | --- | --- |
| 开发，8 图 | 0 / 65 | 6 / 14（42.9%） | 8 | 0 / 14 |
| 留出，8 图 | 0 / 61 | 0 / 14 | 14 | 不用于调参或选择 |
| 合计 | 0 / 126 | 6 / 28（21.4%） | 22 | — |

4 个真实文字区域和 19 个装饰区域没有被 OCR 识别，未计为过滤成功。几何匹配没有歧义或未匹配行。开发命中集中在两列图标；留出常只有一至两个被识别图标、合并为多字符或呈水平排布，不满足现有互证条件。开发中的 Q/N/L 列最后一项有真实旋转投影，因此被保留，不能丢掉几何后声称命中。

**本轮尚未证实泛化收益，策略不达标，保持默认关闭。** 后续需要更丰富的实际截图和质量／像素证据；如继续用本次留出分析调整，必须另建新的独立留出集。不能只展示开发成功图或把合计零误删解读为普遍安全性。

逐图报告为 `output/ocr-filter/report-all.html`，逐行与指标为 `evaluation-all.json`，成功／失败代表对照为 `comparison.png`。报告已用无窗口浏览器核对 16 场景、16 张图片均可加载、页面无横向溢出。
