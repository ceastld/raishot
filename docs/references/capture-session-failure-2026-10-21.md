# 截图会话异常退出与恢复

## 已确认的范围

“截图会话异常结束，请重新触发。”由托盘在截图工作进程非零退出时显示。这个提示合并了普通初始化错误、Rust panic 和 Windows 原生异常，不能据此确定某个用户的具体原因，也不能判断是否每次发生。

维护者补充自己遇到时截图界面尚未出现，优先排查启动、采集和首屏初始化；外部反馈者的出现阶段与频率仍未知。

本机当前数据目录没有对应的近期截图失败记录。现有 Windows 应用错误记录属于较早的开发版，不足以解释用户这次反馈。

## 修复

- 快速框选首屏在显示、合成后检查实际前台、活动窗口和键盘焦点。此前焦点争夺被当成整次会话失败；现在首屏回收后沿用同次冻结图打开 GPUI，继续走其实际焦点检查。未取得焦点的窗口不报告 Ready，显式首屏验证仍直接报告失败。
- 取消仍作为取消传递，不借回退继续打开窗口。已冻结原图的读回失败也不重新采集，保留原截图时刻。
- 显示设备 DC 的像素格式或坐标映射不受支持时，使用有类型的兼容性错误进入已有 DXGI 回退。跨工作线程保留分类；物理尺寸变化、内存限制和清理失败继续终止请求。
- 工作进程入口安装 panic hook，失败时才记录正文、线程、源码位置与有界回溯；保留原 hook。直接启动截图的普通错误也写入现有失败记录。
- 托盘补记子进程退出码，包含十六进制 Windows 状态，独立保存，不覆盖工作进程记录的具体阶段。

## 诊断文件

默认目录为 `%LOCALAPPDATA%\RaiShot\diagnostics`，设置 `RUSTSHOT_DATA_DIR` 时跟随该目录。

| 文件 | 用途 |
| --- | --- |
| `last-capture-failure.json` | 最近一次具体错误或 panic，包括版本、时间、进程及阶段 |
| `capture-failures.jsonl` | 最近最多 200 条具体错误，保留线程 panic 后外层错误处理之前的正文 |
| `last-capture-worker-exit.json` | 最近一次由托盘发现的异常退出，包含父子进程与原始退出码 |
| `capture-worker-exits.jsonl` | 最近最多 200 条进程异常退出 |

成功启动不新增诊断文件读写；记录不包含截图像素。panic hook 无法在访问冲突或 DLL 初始化失败时运行，这类故障仍可由托盘保存退出码。若用户仍遇到问题，需取得同一次失败的上述记录，并核对触发方式、出现阶段及是否每次发生。

## 验证与待验

`cargo check --locked --bins` 通过，只有原有未使用代码警告；`cargo test --locked --lib -- capture_failure capture_activation_tests fast_capture::` 的 39 项定向测试全部通过，覆盖焦点回退、取消保留、设备错误分类与跨线程传递、清理失败优先，以及诊断字段和文件保留。

拖动遮罩探针目录缺少可执行文件，本次未做该专项；没有更新当前运行版。远程或虚拟显示设备的真实格式差异、用户现场的焦点竞争与原生崩溃尚未复现，托盘通知到可框选的启动时延未实测。
