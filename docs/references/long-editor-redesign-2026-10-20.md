# 长截图完成流程（2026-10-20）

## 删段与裁剪合一的编辑界面 v2（10-21 晚）

原型入口：[长图编辑 v2](../design/long-editor-v2.html)（测试台 `/design/long-editor-v2.html`），示例长网页由原型自绘。用户确认原调整窗“拖选删段”最顺手，要求保留并与标注同窗，因此取代下节“不做中间删段”的取舍；下节的工具库、对象检查器与原生接入边界仍有效。原生接入进度见下节。

### 不分模式的分区

- 图内按当前工具：默认“剪辑”工具（数字 1）上下拖动即选段，与原调整窗一致；标注工具下图内用于绘制。
- 图片左侧的剪辑轨：任何工具下都能拖动选段，标注时不必切回剪辑工具。
- 图片外缘是裁边把手，任何工具下可用；剪辑工具下边线内侧 6px 也命中。左右把手跟随视口垂直居中。
- 其余空白处拖动平移；空格或中键同样平移。

### 选段与删除

- 起拖阈值 3px；红色半透明带加两条红线，剪辑轨标出将实际去掉的像素（已删部分不重复计）。
- 松手后浮条：删除（Delete／Enter／Backspace）、仅保留（K）、取消（Esc）；选段触及首尾时“删除”改称“裁掉开头／结尾”。
- 红线可再拖；↑↓ 微调 1px，Shift 10px；拖过画布上下边缘自动滚动。单击放蓝色起点，Shift+单击选到这里，缩略图上 Shift+单击同样扩展，长距离选段不必拖过整张图。
- 吸附：选段、裁首尾与调整删除段时吸附到空白行段（整行同色、至少 6 行）的中线；删后上下各留半个间隙，正好拼成一个自然间距。按住 Alt 暂停，参数条可关。
- 删除即生效、一步撤销；以选段起点为锚，上方内容不动。

### 删除不破坏原图

- 文档只记录长轴上被删的原图区间（含首尾裁剪，相邻重叠自动合并）和横向保留区间，像素与标注坐标都不改。
- 默认收起显示，所见即成品：每处删除留一条锯齿接缝，剪辑轨上有红色标签。悬停标签预览被删内容（过长时首尾各取一截），可“原位展开调整”或“恢复”。
- 原位展开：被删区域压暗加斜纹插回原处，上方内容不动；拖两条红线调整范围，拖到重合即恢复。H 一次展开或收起全部，位置保持。
- 首尾裁剪：拖顶／底把手时临时露出已裁部分，向外拖即恢复，松手收回。左右裁剪保留压暗区，可直接拖回。剪辑面板显示并可输入四边裁掉的像素。
- 顶栏“删 N 段 · 裁 M 边”切到剪辑工具并展开属性栏里的删除记录：逐条定位、单独恢复或全部恢复。

### 标注与删除共存

- 工具库与对象检查器直接复用下节首版的同一套模块（工具目录、渲染器、标注交互与样式），22 项工具、属性／对象检查器、多选组合、套索等行为与下节一致。工具栏开头换成“剪辑、选择”；剪辑工具沿用模块里“裁剪”工具的约定，该工具下模块不处理标注手势与按键。
- 剪辑作用在图片与标注叠好的画面上：标注存原图坐标，显示时按保留片段切开（每段一张只露出该区间的 SVG），导出时图片与标注逐段拼接。完全落在删除段里的随段隐藏（提示数量，恢复即回来）；跨接缝的像图片一样被剪开。
- 取舍：曾考虑把跨接缝标注按成品坐标压缩，但旋转、文字、曲线、聚光灯和水印都没有一致的压缩定义，原生也要逐种变换；“叠好再剪”对所有工具一致，原生按条带渲染 Scene 后裁掉删除区即可。代价是跨接缝画的斜线、椭圆会在接缝处错开。
- 右侧属性栏随工具切换：剪辑工具显示剪辑面板（成品尺寸、四边裁剪数值、删除记录逐条定位／恢复、吸附与原位显示开关），其它工具显示首版检查器。数字键 1 剪辑、2 选择、3–8 六组工具（取组内上次用的）、9 套索、0 工具库。
- 套索导出按保留片段分别蒙版；缩略图上的标注去抖后按缩略比例栅格化。
- 撤销栈存改动前的整份快照（删除区间、横向范围、标注与套索），剪辑与标注共用一条历史；一次手势一步，Esc 只取消正在进行的手势。

### 导航

- 缩略图按宽度比例渲染、不为塞下全图压扁；内容超过面板高度时随主画布按比例滚动。半透明滑块表示视口，悬停加深；拖滑块跟手，点滑块外先把视口中心移过去再跟手。
- 缩略图与主画布同一显示：接缝、选段、标注、展开的删除区都画出，接缝旁标删除量。
- 最右侧全长标记尺把整张图压到面板高度，标出视口、删除位置、选段和各标注颜色，点击或拖动跳转。

### 范围与验证

- 原型只做纵向长图，横向按长轴／跨轴对调。原生接入时删除区间进文档模型与撤销，GPUI 只做输入与渲染；输出上限沿用 3200 万像素／单边 65535（顶栏尺寸标红）。
- 前端验证（1280×800 深色）：示例剪辑、接缝悬停预览、原位展开并拖边调整、剪辑工具选段删除、拖顶边裁剪与松手收回、H 往返位置不变、矩形工具下从剪辑轨选段删除并隐藏标注、选择工具移动与撤销、缩略图拖动与跳转、复制预览尺寸与顶栏一致；浅色主题与 700px 窄窗已看。并入工具库后另验：跨接缝画矩形分片拼合、检查器换色、选择移动、选择工具下从剪辑轨删段并隐藏标注、三步连续撤销、工具库 22 项与选取、模糊打码、套索应用后导出（套索内不透明、外透明）、文字输入框定位、复制／全选／组合及撤销；首版页面在模块加钩子后仍无报错。整图导出约需 2–3 秒（整图 SVG 栅格化）。真实拖动手感、横向长图、原生接入未验。

## v2 原生接入计划（10-22）

界面以原型为准：测试台 `/design/long-editor-v2.html`（`.claude/launch.json` 的 `workbench`）。逐步落地，每步能单独编译、测试和回退；交互细节不在此重复，按上文 v2 各节对齐。

### 取舍

- 宿主：现有图片编辑器（`image_editor.rs` 的 `CaptureView`）新增“剪辑”工具（数字 1），不另开窗口；22 项标注工具与检查器沿用原生实现，不照搬原型的 SVG 近似。
- 底图：前 7 步先物化整张原图；原图超过 3200 万像素或单边 65535 时，“裁剪”仍走旧调整窗。第 8 步改为按共享条带分块，再取消回退。
- 入口：“完成 ✓”仍直接复制；只有“裁剪”改开新编辑器。旧调整窗（`long_editor.rs`）保留至第 8 步取消超限来源回退后再删除，避免第 7 步提前删掉仍需使用的回退入口。

### 步骤

1. **剪辑模型**（新建 `long_clip.rs`，纯逻辑）：轴向、被删原图区间（含首尾裁剪，相邻重叠合并）、横向保留范围；原图↔显示坐标换算（落在接缝上的归属要定义）、保留片段、成品尺寸与超限判断、空白行吸附表（整行同色且不少于 6 行，打开时算一次，取中线）。横向用 `long_editor_model.rs` 的 `along`／`compose` 对调。验收：`cargo test --lib long_clip`。
2. **进文档与撤销**：剪辑层挂在 Document，删除／恢复／调整删除段／裁边各为一个增量命令，与标注共用历史；一次手势一条，取消和无变化不提交。验收：过滤测试覆盖“删段→画标注→撤销三步”等混合历史。
3. **导出**：整张原图渲染 Scene（含套索）后按保留片段拼接，完全落在删除段内的标注随之消失；复制、保存、贴图、历史走同一路径并检查上限。验收：拼接与接缝像素单测。
4. **画布显示与输入换算**（风险最大）：保留片段依次拼接显示，接缝画锯齿；标注按片段裁开显示。所有指针输入只在 `client_point`／`canvas_viewport` 一处做显示→原图换算，现有工具不改。重点实测工具几何、文字输入框定位、OCR、套索。
5. **剪辑工具交互**：选段（3px 起拖、红带）、浮条（删除／仅保留／取消，触及首尾改称裁掉开头／结尾）、拖红线、方向键微调（Shift 10px）、单击起点 + Shift+单击扩展、拖到边缘自动滚动、吸附（Alt 暂停）；左侧剪辑轨与外缘裁边把手在任何工具下可用。
6. **删除记录与剪辑面板**：接缝标签悬停预览、原位展开调整、H 全部展开／收起且位置不变、单条或全部恢复；右侧剪辑面板显示成品尺寸、四边裁去像素（可输入）、删除记录与开关；顶栏“删 N 段 · 裁 M 边”。
7. **导航与替换调整窗**：复用 `long_editor_model.rs` 的 `Minimap` 做缩略图与全长标记尺；`long_output.rs` 的 `Crop` 改开新编辑器并保留“继续采集”回到面板；改写 `long_editor_smoke`、`long_pipeline_ui_smoke`、`image_preview_smoke`，更新 `docs/behavior.md`；超限来源仍需旧调整窗，随第 8 步一起移除。
8. **不物化大图**：底图直接读 `StitchSnapshot` 条带分块，去掉第 1 步的回退限制。

### 协作

- 第 1–3 步只动新文件与 Document／Editor 的剪辑命令，可先行；第 4、7 步动 `image_editor.rs`、`long_output.rs` 前先看 `git diff`，避开其它会话的段落。
- 每步交付：改动文件、跑过的命令与结果、未验范围；真实界面做不了就写“真实界面未验”。

## 统一编辑与裁剪的前端方案（10-21）

> 删段取舍已由上节 v2 取代；本节的工具库与对象检查器已原样并入 v2（同一套模块），原生接入边界仍有效。

原型入口：[统一长图编辑](../design/long-editor.html)，示例为同目录静态长网页。
这是独立前端交互原型，尚未接入 GPUI、采集会话与原生输出流程。

### 同窗布局

- 左侧保留选择、裁剪与套索入口，标注按形状、线条、标记、文字、打码、擦除六组组织；工具库可搜索全部 22 项现有工具，编辑与裁剪始终在同一窗口。
- 中间为居中的可滚动画布；右侧常驻完整长图总览，以及当前工具的参数。
- 顶部保留撤销、重做、适合宽度、完整显示、实际尺寸和输出入口。
- 本方案不做中间删段；主图拖动不再默认选中待删除的一段。

### 裁剪合同

- 裁剪独立保存草稿和已应用范围：拖边、移动保留区与数值输入只更新草稿。
- 保留区清晰显示，范围外压暗；显示实时输出尺寸与超限原因。
- “应用裁剪”或 Enter 把有变化的草稿作为一个可撤销操作提交，并回到编辑。
- “取消”或 Esc 丢弃本轮草稿；拖动中按 Esc 先取消当前手势，不连带退出裁剪。
- 再次进入裁剪时显示完整原图，以已应用范围作为起点；允许向外扩展或恢复原图范围。
- 标注保留原文档坐标；裁剪只决定显示与输出范围，不移动、删除或物化已有标注。
- 有未应用草稿时切换工具，提示先应用或取消；输出入口先应用当前范围，再打开成品预览。

### 长图定位与精调

- 总览的视口框负责点击／拖动浏览；裁剪端点放在外侧轨道，分别命中，不混用同一个拖动区。
- 主图单击放置位置线，再选择“设为起点／终点”；不必把边界拖过整张长图。
- 四边参数显示裁去的像素，各自提供定位按钮；主画布拖边与参数、总览端点同步。
- 滚轮浏览，Space＋拖动或中键平移，Ctrl＋滚轮围绕指针缩放；切换工具保留阅读位置。
- 选中边界后方向键微调 1px，Shift 为 10px；Home／End 到首尾，PageUp／PageDown 翻页。
- 数值输入时快捷键让给输入框；拖边越过画布边缘可自动滚动，松手或取消即停止。

### 接入原生的边界

- 复用共享条带、分块预览与总览导航；进入裁剪只改几何，不提前生成整张长图位图。

## 为什么去掉独立的长图编辑窗

> 10-20 晚：用户在图片编辑器里裁长图后反馈“右侧点击预览没了、窗口不居中”，调整窗已从备份恢复为“裁剪”入口；✓ 改为直接复制。下面是当时去掉它的理由，留作取舍记录。

- 10-20 上午把旧的“浏览／裁剪／删段”三模式编辑窗重写成不分模式的调整窗（拖选删段、拖边裁剪、总览条、分块缓存）。用户实测仍觉得“鸡肋”：完成后弹出一个陌生窗口，只能裁和删，要标注还得再点“标注”换到图片编辑器；当时还反馈“点了没反应、拖窗口才出下一帧”。
- 用户选定：完成后直接进图片编辑器，标注、裁剪、复制／保存／贴图都在同一个熟悉的地方；采集中仍可“撤销最后一段”。中间删段功能取消。
- 上午那版调整窗的源码没有提交，删除前备份在会话临时目录（不在仓库内）；如需找回，从 git 历史只能拿到更早的三模式版本。

## 新流程

| 入口 | 行为 |
| --- | --- |
| 完成 ✓ / Enter / Ctrl+C | 排空尾帧并暂停确认后生成成品，直接写剪贴板并记入历史，结束会话（下午改：打勾进编辑器太难用） |
| 裁剪 | 隐藏边框、侧预览与操作条，用共享条带打开长图调整窗（不物化）；窗内输出或“标注”后结束会话，“继续采集”或关闭回到面板 |
| 保存 / Ctrl+S | 生成成品后打开保存面板；保存成功结束会话，取消则回到采集面板 |
| 贴图 | 生成成品后直接贴出，贴图首帧呈现后结束会话；首帧失败回到采集面板 |
| 取消 / Esc | 关闭 |

- 生成成品期间操作条留在原处，状态行显示“正在生成长图…”，控件停用；以前直接贴图时先隐藏一切再在后台生成，大图时屏幕上一段时间什么都没有。
- 输出失败或保存取消：恢复边框、侧预览与操作条，状态行显示原因；请求输出时正在采集的，按原自动滚动目标继续。
- 成品超过 3200 万像素或单边 65535：提示行显示超限；点任何输出都不置灰，而是说明“撤销最后几段或缩小选区宽度后再完成”。

### 10-23 采集工具栏 C 方案

- 前端 `docs/design/long-capture-toolbar.html` 的 C 方案已确定：拖柄、移动选区、暂停／继续、自动滚动、撤销、设置 ｜ 裁剪、保存、贴图 ｜ 完成复制、取消，主栏全部为图标。自动滚动保留方向图标，暂停后改播放图标；完成仅图标用强调色。

### 10-24 自适应自动滚动

- 开始或恢复自动滚动时从慢速起步，不再提供固定速度档。每次匹配直接传出综合误差、匹配行比例、视觉唯一性及共有正文重叠比例；精确重复帧没有新的质量证据。这些数值是匹配器的启发式证据，不是校准后的置信概率。
- 内部倍率从 1 起，每两次连续高质量滚轮响应增加 0.5，上限为 10；误差不超过 2、匹配行至少 90%、正文重叠至少 65% 且视觉唯一时才获得提速资格。一次平滑运动累计最弱证据，只在下一次实际投递时奖励一次。
- 误差超过 4、匹配行不足 80%、正文重叠不足 45%、视觉不唯一或匹配被拒绝时立即按 0.6 回退，最低为 1。同一次响应只回退一次，恢复后须重新连续可靠才能加速。发送至可再次发送的耗时超过当前间隔（至少按 30ms 计）的两倍，也按慢响应回退。
- 半格发送间隔为 100ms／倍率，运动后静止观察为 30ms／倍率平方根。每步仍为半格 60，最多两个未确认半格；只有当前代投递之后的新帧能确认运动或影响速度，旧许可、静止和零位移匹配不能制造提速证据。拒绝后的背压／停止、目标归属校验和输出排空保持。
- 验证：`cargo check --lib --tests` 通过（既有未使用警告）；`cargo test --lib long_auto` 29 项、`cargo test --lib stitch_stream_` 5 项通过，覆盖提速／回退、平滑动作只奖励一次、整格目标、旧帧隔离、拒绝恢复及双轴质量出口／固定栏正文比例。真实网页、设置浮层与混合 DPI 未验；运行副本未更新。

## “点了没反应”的排查记录

- 用本机 QA 探针（`target/qa/flicker-probe --long-edit-test N --scroll-ms 8000`，不进仓库）沿真实托盘路径：触发截图→投递拖拽框选→L→自有深色滚动窗滚出约 4800px→点完成→向编辑窗投递悬停、滚轮、总览条点击、拖选、Delete、拖边。用 GpuiPresentSerial 计数确认出帧，用 DXGI 桌面复制确认屏幕像素变化。
- 结果：上午那版调整窗在这条路径上每次操作 5–40ms 就上屏；静止时主线程与 vsync 线程都在正常运转，同进程隐藏窗口没有残留更新区域，未复现用户描述的卡住。之后用户也反馈“似乎有反应了”。原因未定位，可能是间歇性的；独立窗口已去掉，此项不再跟进。
- 新流程（同一探针加 `PROBE_FINISH=1`，点主栏最后的“完成”）：142ms 打开图片编辑器、采集面板已回收；编辑器内悬停 1–72ms 出帧、滚轮 8–89ms 上屏；关闭编辑器后会话进程退出。
- 探针注意：用户在用电脑时编辑窗可能被其它窗口盖住，屏幕像素检查会误判为“没变化”；只截自有窗口区域，截图用后即删。

## 隐藏窗口 WM_PAINT 风暴（10-20 上午修复，仍有效）

- 现象：编辑期间隐藏的采集面板每秒收到数万次 WM_PAINT，主线程 40–80% 空转在 GetMessage 内核里，约 2/3 次采集→编辑出现。
- 原因：GPUI 处理 WM_PAINT 只 `ValidateRect` 客户区；隐藏窗口的更新区域还可能带窗框、待擦除或内部绘制标志，不调 `BeginPaint` 时永不清除，系统无限重发。
- 修复：`vendor/gpui/src/platform/windows/events.rs` 的 `draw_window` 改为 `RedrawWindow(RDW_VALIDATE | RDW_NOFRAME | RDW_NOERASE | RDW_NOINTERNALPAINT)`；采集面板在输出交接期间停掉逐帧回调与 50ms 重绘。
- 10-21 用户再报“裁剪窗只有拖动窗口才刷新、点右侧总览条没反应”。探针沿“框选→L→滚动→点裁剪”复现约 1/4：调整窗静止 1 秒出帧 0、主线程约 860ms CPU，悬停与总览条点击都不出帧。新增的主线程栈采样（挂起线程 + StackWalk64 + PDB）显示 300 个样本全在 `GetMessage → DispatchMessage → 面板子类过程 → GPUI draw_window → RedrawWindow`，此时隐藏的操作条 `IsWindowVisible=false` 却 `GetUpdateRect=true`：上面的修复没清掉。
- 小实验确认机制：`ShowWindow(SW_HIDE)`／`SWP_HIDEWINDOW` 隐藏时系统会清掉更新区域；窗口若在带着更新区域时经样式位变为不可见，`RedrawWindow(RDW_VALIDATE…)` 与 `ValidateRect` 对不可见窗口都是空操作，WM_PAINT 无限挂起，饿死同线程调整窗的 WM_PAINT（拖动窗口时模态循环自己驱动绘制，所以“拖一下才刷新”）。只有 `BeginPaint／EndPaint` 能清。
- 修复：`draw_window` 清除后若更新区域仍在，再 `BeginPaint／EndPaint`。同流程复测 10/10 正常：悬停 1–8ms 出帧，总览条点击 3–11ms 出首帧，静止主线程约 0ms，隐藏操作条不再残留更新区域。
