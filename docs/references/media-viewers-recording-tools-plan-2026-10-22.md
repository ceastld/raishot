## 1. 目标与先后顺序

媒体集成与该批Dev验证已由视频核心／音频负责人接管：分块混音保存及历史内嵌预览已接，Dev程序已构建、重启，正式CLI的CFR／VFR三例通过。定向与原生结果及待验范围集中见[音频专题](media-audio-processing.md)；后继源码与真实三入口验收不继承此前结果。

后继未完成输出回滚、请求时刻暂停／停止与音频边界、六档画质／初始码流头、先录后码、质量速度请求及显式缩放技术入口的验证见[录屏专题](recording-output-lifecycle-2026-10-11.md)；有限SVG及图片预算各批结果见[图片专题](image-animation-streams.md)。这些后继源码尚未更新到运行中的Dev程序，真实界面与设备另验。

把 RaiShot 的截图、查看、编辑、录制、处理、保存和再次打开接成完整工作流。每项功能同时考虑入口、参数、执行、取消、错误、输出和再次打开；菜单存在、模型通过、系统支持某编码，都不能单独代表功能已经可用。

第一优先级是用户已经遇到的可用性问题：**从主界面和普通文件进入内置视频查看，画面、声音、暂停、进度跳转和关闭都正常**。同时保留现有录屏结果窗的行为，明确用户当前播放失败的实际入口和表现。随后补齐图片查看与常用格式，再深化录屏质量、可靠性和工具。

| 优先级 | 含义 | 本轮主要内容 |
| --- | --- | --- |
| P0 | 打通核心工作流，解决当前明显不可用 | 视频问题复现、播放核心、内嵌音轨、视频窗口、历史入口；最小公共接口和编码路径识别 |
| P1 | 日常高频能力，第一轮产品化 | 图片目录浏览、缩放、常用图片/动图、视频快捷操作、缩略图、录屏预设、音频设备、长录制安全 |
| P2 | 在稳定基础上拓宽工作流 | 批处理、多页图、颜色管理、条件格式、高级编码、轻量视频处理、图库管理 |
| P3 | 技术与使用价值需要先验证 | 特殊图像格式、摄像头、先录后码、字幕与演示加工、可选本地模型工具 |

阶段按可验证的结果推进，不用预计日历日期代替完成度。P0 可以复用现有模块直接接通；公共能力只做当前任务确实需要的最小部分。

## 4. 公共行为与数据边界

1. **查看与编辑衔接**：打开源文件首先只读查看；进入标注/调整后使用现有 Document / Editor / Scene。编辑版本、查看变换、源文件信息分别保存，原片输出与当前效果输出各有清楚动作。
2. **图片内容与显示投影**：缩放、平移、棋盘格、窗口主题不改源像素。EXIF 方向、颜色变换与帧/页选择有明确坐标映射，OCR、标注、裁剪和导出使用同一含义。
3. **视频来源**：普通媒体文件、录屏临时结果、已发布成片分别持有来源和生命周期。外部文件播放不授予清理/删除权限；录屏库保留当前固定目录、完整文件和身份检查。
4. **任务生命周期**：解码、缩略图、处理、导出共享最小取消与代次规则；换文件、换参数、关闭窗口后旧结果不能覆盖新状态。UI 线程不等长解码、整轨读取或编码结束。
5. **音视频播放**：用媒体时间戳和明确主时钟推进；缓冲有界；seek 使旧音频/画面失效；无音轨、变帧率、长 GOP、结束和解码失败都有状态。
6. **编码能力**：容器、视频编码、音频编码、像素格式、位深、质量控制、硬件策略分别描述。枚举成功后仍需协商和试编码；CPU 像素输入与软件编码是两个字段。
7. **保存事务**：复用原子写出、原文件保护、同名确认、取消和发布成功后记历史的规则。快速视觉预览与精确编码结果带相同参数版本，保存只能使用当前有效结果。
8. **资源与进程**：托盘及待命不因增加查看器初始化 GPU/编解码。图片和视频按需拥有工作进程/会话，关闭后释放设备、声音、线程与缓存；GPU 共享需要独立证明可行。
9. **产品一致性**：GPUI 原生界面，中英文字、系统主题、键盘、混合 DPI、负坐标多屏沿现有规则。查看器的窗口工具和标签不进入输出。
10. **本地读取范围**：目录浏览与预取只检查用户明确打开的目录，默认不递归。读取前检查 Offline/RecallOnOpen/RecallOnDataAccess 与链接目标，跳过云端占位和云盘链接；用户明确选择的具体云盘文件按其请求处理。失败保留当前图，不因邻图预取触发下载。

公共接口先覆盖打开请求、媒体描述、播放状态、帧、取消和导出结果几种实际消息；可暂用现有结构适配。命名和具体文件由 B01 的集成人定稿，后续任务不各自建立平行协议。

## 5. 格式支持目标

### 5.1 图片：读入、动画/多页、写出分别验收

“目标”表示本计划希望做到；当前实际支持由 F01 的样本结果确定。系统安装的编码扩展和依赖特性只作为能力来源，界面按当前构建与当前机器的实际探测展示。

| 格式 | 读取与查看目标 | 写出目标 | 顺序与边界 |
| --- | --- | --- | --- |
| PNG | 透明、灰度、常见位深、正确色彩与大尺寸 | 继续现有压缩、透明与流式长图保存 | P1 核心；16 位源信息另验 |
| JPEG/JPG | 基线/渐进、EXIF 方向、ICC；特殊颜色输入单列 | 质量、背景合成、明确元数据策略 | P1 核心 |
| BMP | 常见位深与 alpha 含义 | 继续现有输出 | P1 核心 |
| WebP | 静态透明、无损/有损；动画另验 | 静态无损/有损与质量 | P1 静态，P2 动画输出 |
| GIF | 帧时长、循环、透明、处置方式、暂停逐帧 | 复用现有导出，增加片段与参数 | P1 动画读取与成品验收 |
| APNG | 正确帧合成和循环 | 按体积/性能决定实验输出 | P2，独立于静态 PNG |
| TIFF/TIF | 多页、方向、压缩/颜色的已验证子集 | 单页优先，多页另验 | P2，明确页数与位深限制 |
| ICO/CUR | 多尺寸/多帧选择，透明 | ICO 输出按需求单列 | P2，图标集合不当普通动画 |
| AVIF | 单张及 HDR 元数据探测；序列另列 | 能力通过后实验输出 | P2，有依赖与性能门槛 |
| HEIC/HEIF | 方向、多图容器、主图与可解码状态 | 先不承诺通用编码 | P2，系统/可选组件条件支持 |
| SVG | 原生离线栅格化，明确背景/尺寸，禁外部资源自动加载 | 导出当前渲染图；保留源文件 | P2，查看与有限栅格化 |
| JPEG XL | 静态/高位深能力验证 | 价值与分发成本评估后决定 | P3 实验 |
| EXR/HDR | 高动态范围源信息与 SDR 映射 | 先保留源文件/导出明确的 SDR 副本 | P3，与现有截图 HDR 路径分开验收 |
| RAW/PSD | 可用预览/合成图，明确不支持的部分 | 保留原文件，另存常见图片 | P3 技术验证，不承诺完整图层编辑 |

图片底层当前会转 8 位；F08 落地前，高位深源不能宣称无损往返。元数据读取、保留、移除分别可控，截图生成文件继续沿现有默认规则。

### 5.2 视频：以组合定义能力

| 目标组合 | 目标阶段 | 需要证明的内容 |
| --- | --- | --- |
| MP4 + H.264 + AAC | P0 基线 | 本应用录屏与外部普通文件均有画有声、seek/暂停/关闭正常 |
| MP4 + H.264，无音轨 | P0 基线 | 不将无音轨当失败，结束与重播正常 |
| MOV/M4V + 可用音视频流 | P1 | 容器解析、旋转、时间戳、实际解码；MOV 中不同编码分别记录 |
| AVI/WMV 等常见旧文件 | P2 | 只开放实测的容器/流组合，损坏文件反馈明确 |
| MKV + H.264/HEVC 等 | P2 条件 | 容器支持与解码支持分开探测；多音轨/字幕另验 |
| WebM + VP8/VP9/AV1 + Opus/Vorbis | P2 条件 | 当前媒体后端能否打开容器及两类流；缺少其中一环就提示具体限制 |
| MP4/MKV + HEVC 或 AV1 | P2 条件 | 系统/组件、profile、位深、显卡能力及音轨组合分别验收 |
| 4K、高帧率、HDR、变帧率 | P2/P3 专项 | 有界资源、实际丢帧/音画偏差、颜色、旋转和显示器切换 |

后端路线：先复用系统媒体链路交付 H.264/AAC 基线；再用真实格式矩阵决定是否增加独立原生解码/封装组件。若新增组件，先完成最小样本验证、体积/启动成本与分发方案，再接生产。系统媒体能力区分容器与编解码，见 [Microsoft 媒体格式说明](https://learn.microsoft.com/en-us/windows/win32/medfound/supported-media-formats-in-media-foundation)；该列表也不能代替当前机器探测。

### 5.3 录屏输出与策略

| 能力 | 目标 | 开放依据 |
| --- | --- | --- |
| MP4/H.264/AAC | 可靠默认输出，兼顾文字与运动 | P0/P1，保留兼容基线 |

## 7. 第一轮落地次序与后续里程碑

### M0：视频可用性闭环

## 8. 多对话并行：所有权与交接

### 8.1 先认领文件，再开始写

当前工作区已有多处未提交改动。所有会话先 `git status --short`，读取本地交接，修改前检查该文件 `git diff`。只改自己负责的 hunk；原有改动和其它任务保持。

共享入口由**一个集成对话**维护：`src/lib.rs`、`Cargo.toml`/`Cargo.lock`、二进制入口、`file_launch_command.rs`、`main_page.rs`、`settings_view.rs`、`main_history.rs` 的路由与页面挂载、托盘/工具栏注册。其它对话交付需要增加的模块声明和调用说明，由集成人窄接。

## 9. 最小验证矩阵与完成定义

| 范围 | 自动/成品验证 | 人工验收 |
| --- | --- | --- |
| 图片 | 文件头/坏输入/资源边界；方向、alpha、帧合成；编码后重新读取 | 翻图、缩放、透明背景、动图控制、查看进编辑、主题/DPI |
| 视频 | 探测与状态；seek代次、时间戳、缓冲；关闭回收 | 三入口有画有声、拖动/键盘seek、倍速、全屏、结束重播 |
| 录屏 | 预设/能力匹配；停止/发布/失败事务；成片探测 | 实际采集、设备、静止文字与运动、长录制、暂停恢复、再次播放 |
| 工具 | 自有合成输入验证尺寸/alpha/帧页/顺序；取消不覆盖 | 参数预览、保存当前结果、批量部分失败、再次打开成品 |
| 图库 | 索引迁移/来源限制/缓存失效/删除范围 | 可见项优先、快速预览、返回位置、失效文件、撤销 |

测试只覆盖能证明本次改动的必要范围；沿仓库顺序先 `cargo check`，必要时过滤模块测试，再按需 Dev 构建和实际运行。文案、小布局等可逆修改不补镜像实现的测试；不跑全量格式化或不相关测试。真实界面暂时做不到就标“真实界面未验”，继续独立任务，相关新入口仍保持内部/实验。

性能先记录同一台机器、同类自有样本的基线，再比较首帧、翻图/seek延迟、CPU/GPU、内存和退出释放。托盘截图约 200ms 的口径继续独立，只改启动路径时才测；不拿 CLI 捕获速度或编码器名称替代用户交互证据。

一项任务完成要能回答：从哪里进入，处理什么输入，参数是否真的生效，失败/取消留下什么，输出是否能再打开，谁验过哪些场景，现在开放到哪一级。全计划按这一粒度持续交付。

## 10. 下一批实施边界

V06 先做最多128项显式路径队列，同一窗口只有一个活动播放器；选择、拖入和CLI最终共用该队列，坏项显示错误且仍能切换。旋转由播放核心单点归一像素与显示尺寸，PTS保持；窗口和帧输出继续复用同一帧，避免分别旋转造成所见与导出不同。

V09 拖动时保留原播放状态，预览与最终提交区分；精确定位以目标时间前后的真实帧PTS确定，不将关键帧或未来首帧直接当成目标。V10 以设备实际播放位置映射媒体时间，padding只表示待播队列；暂停冻结、Reset重新锚定，旧代时钟拒收，外推受已排队媒体上限限制。音量调整与transport代次分开，欠载和EOF不能靠墙钟跳过已排队尾音。先做纯模型，再接设备，最后以实际呈现与设备时钟的同QPC观测验证；文件回读不算实播同步通过。

F04 采用流式GIF来源，保留合成画布、Previous所需局部恢复区、当前索引块和有界交付帧；不收集整段动画。透明索引跳写，Background按有效背景规则清前帧区域，Previous还原覆盖前像素；零延时、UserInput和有限循环分别有明确语义。默认动画预算独立于静态32MP限制，超出时明确退回首帧查看，不能直接放宽预算。来源核心先独立验证，再由图片查看对话接入现有单worker。

R02 分两步：先为显式策略提供单次尝试后端，并复用一次目录探测和同一质量参数，按实际编码器观测接受或拒绝；Unknown不能满足仅硬编或仅软编。再接录制首帧事务：首样本成功前保留原队列，已接受任一音频或视频样本后停止回退；失败尝试使用录屏输出事务分配的自有暂存，不能任意改名或清理文件。默认录制路径和正式策略设置待这两步成片验证后再调整。
