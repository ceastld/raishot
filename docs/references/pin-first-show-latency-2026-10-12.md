# 中键贴图首显提速

用户反馈中键到贴图出现约 1～2 秒。本次只处理生成和首显，拖动、缩放及后续自动保存另按实际反馈排查。

## 瓶颈与改动

旧运行版在同机受控中键输入下，到实际 Present、显示和 DWM 完成的回执为 **1084.0 ms**；选区像素准备仅 **1.1 ms**，新贴图窗口渲染管线初始化为 **971.2 ms**。测试沿真实截图→贴图路径，独立设置目录、关闭历史，不操作剪贴板。

- GPUI Debug 每窗原会现场编译 18 个管线入口。有 FXC 时，`vendor/gpui/build.rs` 以 `/Od /Zi` 在构建期生成全部 20 个入口，包含 Emoji；三份 HLSL 和编译器环境变化触发重建。无 SDK 时保留固定在 EXE 内的源码，成功字节码按入口缓存，失败允许重试。GPU 对象和可变缓冲仍每窗独立。
- `pin_presentation.rs` 在严格整数 1:1 显示时按行复制底图，保留多平面覆盖、光标叠层和透明像素语义；分数偏移、缩放、空洞和短缓冲保留原采样路径。实际模型计时：800×600 从 **17.5 ms 到 0.8 ms**，1920×1080 从 **78.7 ms 到 4.1 ms**，结果逐字节一致。
- `pin_view.rs` 仅将截图交接的新窗口工作区登记移到真实首显 accepted 回调后，登记与下一次输入之间不让出事件循环；普通及恢复窗口仍保持原组显隐时序。同一 Arc 的原图和当前图不重复核对一次像素，独立图像仍完整检查。

## 验证范围

最终 `cargo check --bin kirie-gpui` 通过，构建期全部着色器成功生成。底图／外观相关同批 51 项模型中，49 项通过、1 项性能测试当时忽略、1 项既有几何预算测试失败；被忽略的性能测试随后单独执行通过，新增 4 项像素合同包含在通过项内。

失败的 `dual_4k_preview_preflight_keeps_48m_frame_budget_and_export_32m_and_corner_limits` 仍期待旧 CPU 四角预算；当前预检已按 GPU 整组内容和 4096 底图分块判断。失败链不调用本次拷贝快路，且该文件未改，本轮不修改该旧测试。GPUI 缓存的两个合同已定义，但 Cargo 拒绝单独测试非工作区成员的 dev-dependencies，本轮未另建工作区。

增量 `cargo build` 完成，三个 EXE 已更新到 `target/qa/tray-run/`，托盘和待命进程已重启。同一选区的新工作进程复测，中键到真实首显回执为 **63.7 ms**，约为旧版的 1/17，耗时减少约 94%；新贴图管线初始化为 **12.4 ms**，首个截图窗口为 **11.9 ms**，两处现场编译等待均已消除。成功回执保持实际 Present、DWM 完成和原截图交接后的关闭顺序。这是一组同机同选区的对比，未推广为所有大小、显示器和硬件的固定耗时。

规范指定的 `flicker-probe --drag-test 3` 完成三轮，两个显示器均未观测到拖动期间的完整未遮罩帧。该探针核截图拖动遮罩，不代替贴图全部像素或全部多屏场景验证；图片／复杂标注／混合 DPI 的其它范围待自然使用确认。
