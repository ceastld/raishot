# 图片工具工作流

图片工具接收已经确定方向的不可变像素快照和原片保护路径。单图变换和分割使用当前像素，成品对比的原图侧使用冻结来源、结果侧使用封存成品回读；双文件对照另行选择两个磁盘文件。批量和拼接明确使用磁盘文件，按列表顺序重新读取。PDF 分别提供当前结果与磁盘文件入口，列表明确区分快照和文件页，不隐式混用来源。

“图片处理”窗只保留“用结果继续”一组：前后对比、分割、取色与测量、识别条码、转 PDF，都等待有效的当前结果；与当前图无关的双文件对照、批量、拼接、文件 PDF 和二维码不再从这里开窗，统一走图库“工具”菜单。图片和历史的当前帧继续通过不可变快照进入图片工具。

## 统一界面（10-25）

所有工具窗共用 `tool_window_chrome`：左侧固定宽参数栏（分组小标题、分段选项、步进、提示），右侧预览台（上方一条细说明栏），底部状态栏左侧是带色点的一句状态、右侧按钮，主操作放最右。窗口标题与图库工具名一致（图片对照、图片分割、取色与测量、识别条码、批量导出），不再写“内部／实验”；正文不再重复大标题，关闭交给标题栏和 Esc。

- 窗口打开时提到最前并取得焦点，但不常驻置顶（`gpui_capture::foreground_tool`），切到别的窗口后按普通层级让位；截图流程里的辅助窗仍用置顶版本。
- 从图库打开的工具在主窗口弹层里显示，不另起窗口；其它入口的独立窗口按工具复用，同一工具再次打开时在原窗口换内容。宿主与复用规则见[工具并入图库 · P2](library-tools-2026-10-23.md#10-p2-合窗10-25)。
- 拼接、转 PDF 的来源是可拖动排序的缩略图格，批量导出是带缩略图、可拖动的分页列表；弹层里“从图库添加”回图库挑图，单图工具在弹层顶栏互切；独立窗口里三个单图工具合成一个窗口，顶栏同样互切。见[来源条与单图互切](library-tools-2026-10-23.md#11-来源条与单图互切10-25)。
- 分割：源图上叠加切线，点哪块选哪块，方向键或 ‹ › 换片，换片只读计划里的矩形，不再为每块重新渲染预览；格式只影响保存。还没选目录时点“保存 N 块…”先选目录再接着保存，结束后可“在文件夹中显示”，失败项逐条列出。
- 取色与测量：模式只有“取色／测距”，测距连续点两下得到 A、B，第三下重新开始；侧栏依次是当前像素、测距结果、采样色（填入转换／复制）、颜色转换。窗口焦点上 Ctrl+C 复制鼠标下的像素。
- 识别条码：码制为可多选的标签，反色为开关；结果列表点选在预览上标出扫描线，每行可直接复制；底部“识别／重新识别”。
- 对照：不加侧栏，顶部一条视图工具条（并排／只看 1／只看 2、交换、缩放组、换图片），面板标题只显示文件名、尺寸和序号，比例显示在面板底部。
- 图片处理：参数改动时保留旧预览直到新预览就绪，右上角提示“正在更新预览”，不再闪成空白。
- 外部入口：`raishot-cli --open-tool compare|collage|pdf|batch|split|measure|barcode <图片...>` 不经主界面直接打开同名工具，最后一个窗口关闭即退出；也用于截工具窗做界面对比。

## 处理与保存

- 变换复用已有旋转、镜像、灰度、反色和亮度；再按指定尺寸缩放。双线性插值按透明度加权，避免透明边缘混入隐藏颜色；它不等同于面积抗锯齿缩小。
- 尺寸既有保持比例的百分比预设，也有明确的最终宽高；精确宽高可能改变比例，旋转不隐式交换这两个目标值。输入草稿只有应用后才改变处理参数，非法或超预算输入保留已经应用的结果；保存使用当前已应用结果。
- 对比度和饱和度在最终尺寸确定后顺序处理，复用现有依赖的对比度和灰度计算；它们在编码 RGB 上调整，不宣称线性色彩运算。默认不改任何像素，alpha 和全透明像素的隐藏 RGB 始终保留，处理逐行检查取消。
- 锐化在颜色调整后处理最终尺寸，默认关闭，内部窗口提供 25%、50%、100% 强度。复用现有依赖的固定 5×5 高斯核，以归一化预乘颜色模糊，只增强反预乘后的 RGB，原 alpha 和全透明隐藏 RGB 保留。256 像素块带 2 像素余量，临时工作集另限 160 MiB；新帧全部完成后才替换，块间及合成逐行检查取消，单块调库期间不响应取消。
- 单图预览保留不可变编码产物，显示真实编码字节数。JPEG、WebP 以及保留颜色配置时的其它格式都由最终编码回读预览；保存复用相同字节。回读将编码 Vec 的实际预留容量计入来源缓冲预算，不只计算有效字节长度。PNG 和 WebP 保留 alpha，JPEG/BMP 将透明部分合成白色；PNG 快速、均衡、最小只改变压缩策略。WebP 默认无损，可显式选择有损及 1–100 质量，质量参数与 JPEG 独立，初始值 90；切换模式保留质量，只有有损使用它。无损沿用既有编码路径，保证可见 RGB 无损，不承诺全透明像素的隐藏 RGB；WebP 仍只在内部工具开放。
- 成品对比冻结同代的原图快照与编码成品，结果侧回读封存字节，包含 JPEG 质量、白底合成及颜色配置处理后的实际像素。打开后父工具再改参数不影响对比，不读取源路径或复制编码字节；完整像素与同步视口的边界见[双图对照](#双图对照)。
- 元数据默认去除，兼容入口保持此默认。有可靠解码上下文时可选“保留颜色配置（不含 EXIF）”，仅封存适用于当前 RGB 像素的 ICC：已转换或明确按 sRGB 处理的像素嵌固定 sRGB，转换失败且有效 RGB 配置与像素仍匹配时才保留该源 ICC。未知、损坏、超限、CMYK 等状态明确失败，不静默降级；BMP 不支持保留选项。来源信息随像素快照移交，工具不通过保护路径重新读取；元数据在编码产物封存前处理，保存阶段不再追加字段。
- 第三种策略“保留颜色及已支持 EXIF”只在来源有已验证字段时可用，使用同一份最终编码回读预览。EXIF 按当前方向和尺寸重新构建，不照搬原始块或偏移；GPS 标签、缩略图、厂商及未知字段不保留。窗口显示源字段中可保留的数量，以及 IFD0/ExifIFD 已扫描标签中未保留的数量，不把未遍历 GPS/缩略图内的字段算入总数，也不声称清除任意用户文本中的位置信息。
- 每窗只有一个重任务槽。变更参数会取消旧预览并合并为最新请求；取消不提前释放槽。保存期间锁定来源和参数，提交前仍检查取消，提交成功后保持成功结果。
- 图片、不可变编码产物与 PDF 共用提交结果判定：成功提交不受晚到取消影响；未提交的写入、同步或提交错误返回后先检查取消，再报告真正的失败。取消和失败都不覆盖已存在目标。
- 批量、拼接和 PDF 的磁盘页共用可取消的有界解码入口，同一取消标记贯穿分段读取、容器元数据与 ICC 处理；返回后先确认取消，再把真正读取错误定位到具体来源。有损 WebP 通过编码进度和输出回调响应同一取消标记；单图封存与批量、分割、拼接共用的直接保存均传入该标记。库内整帧解码、既有调整和其它旧编码器仍在阶段前后响应取消，提交成功后不受晚取消降级。
- 源路径参与路径比较前先检查本地可用性，避免读取云占位或经过链接。快照取得后原片已移动允许另存；输出目录在编码前和提交前检查。默认创建新文件，同名、原片和提交竞态均不覆盖。
- 原生关闭和关闭按钮遵循同一流程：请求取消，等待后台归还，再移除窗口，防止最后窗口退出时打断临时文件清理。

## 双图对照

对照窗既可接收工具的冻结来源与成品，也可只读选择两个本地文件，保留选择顺序及重复项；动画和多页文件读取首帧／首页并显示说明。取消选取、数量错误、读取失败或取消加载都保留旧图对，不修改文件、编辑文档或历史。对照窗工具条上的“换图片…”可另选两张文件。

窗口保留两张完整冻结像素，原图／结果／双栏只改变可见侧。两侧共享归一化中心与相对适应倍率，各自按真实宽高比映射，滚轮缩放、左键或中键拖动与方向键平移同步作用于两侧。“当前侧 100%”按该侧源像素与显示器物理像素计算，不承诺不同尺寸的两图同时为 100%；每侧显示自身实际比例。F 适应，0 设当前侧 100%，1／2／3 切换模式，X 交换两侧，缩放另有加减按钮。

精细画面直接从完整源像素按视口逐行最近邻采样，每侧最多 200 万像素、单边 8192；不通过放大总览补出细节。960×600 以内的总览只在新视口完成前过渡显示，明确标注“非精细像素”；超出物理采样上限的画面明确标注降采样预览。缩放和平移期间保留旧总览，不把过期精细图标成当前源像素结果。

文件图对累计限 3200 万像素，前景解码将第一张新图的实际容量继续计入第二张外部驻留量；换源还预留旧完整图对的实际容量及 64 MiB 显示空间，整对成功才替换。工具成品回读把编码 Vec 实际容量与已冻结原图实际容量分别传给前景预算入口，此时尚未生成预览；冻结图对自身实际容量另限 256 MiB，同一 Arc 不重复计费。这些检查不宣称所有编解码器私有堆峰值都已闭合。

后继宿主预算修复已接源码、待编译及回归：单图成品预览回读另计仍存活的原图、处理帧实际容量和来源元数据驻留量；当前及延迟回收显示槽按 960×600 上限预留，另留一张新小预览。打开成品对照时，宿主额外预留不重复包含解码器正在计费的原图和编码输入；后续换文件则继续预留打开时宿主的原图与编码容量，共享原图通过 Weak 身份与旧图对去重，迁出图对后仍计费。该预留只描述打开时已知宿主快照，不追踪父窗口未来任意任务，也不强持有额外完整图。

加载来源与视口采样共用一个重任务槽，变更合并为最新请求，取消不提前归还槽；任务返回后核对代次、视口、面板尺寸和 DPI，再安装精细结果。采样逐行响应取消，关闭请求等待后台归还；替换的 GPU 图片按窗口绘制生命周期回收。界面、文件选择和 DPI 的实际验证范围见下文，源码接线不作为真实交互通过证据。

## 多图与分割

分割由一个计划统一生成坐标、预览和文件名。支持行、列、网格以及均分、固定像素和比例；累积边界覆盖整图，不丢失不能整除的余数。比例预设为 1:2、2:1、1:2:1，网格将预设同时用于两个轴；自定比例分别输入行和列的正整数权重，显式应用后才更新预览和保存参数。无效草稿保留已经应用的结果，切换方向保留隐藏轴的草稿。逐块处理和编码，取消保留已提交的文件，结果逐项列出。

拼接按列表顺序排列，支持横竖和网格方向、原尺寸/等宽/等高、对齐、间距和背景。拖到来源行上插在该行之前，拖到列表末尾区域移至末尾；顺序实际变化才清掉旧成品，跨窗或过期拖动不生效。网格按行优先，各列宽和各行高取对应缩放图最大值，对齐同时作用于单元格两个轴；尾行不满也不增加空行。内部窗口默认双线性平滑，也可选最近邻像素采样；通过共享逐行采样器和一行缓冲合成，保留旧拼接 API 的既有像素规则。先检查总输入及输出像素预算，再分配成品；成品产生后释放解码输入，再生成小预览。

批量处理只消费显式输入列表，不递归目录。每项依次解码、变换、保存，旋转、水平/垂直镜像、灰度、反色和亮度复用既有基础调整，再按最终尺寸缩放；亮度以 10 为步长，范围 −100～100。对比度、饱和度和锐化也复用单图处理；锐化默认关闭，可选 25%、50%、100%，在最终尺寸上、颜色调整后和水印前执行，保留原 alpha。旧批量调用保持默认不锐化；所有效果在访问单项前统一校验。坏文件不阻断其余项，累计解码和处理预算不因失败退还。命名可保留源文件名加后缀，或使用已有日期、时间、宽高模板；序号按原输入位置追加，失败项不挪动后续编号。结果保留原输入索引，复制路径只包含真实提交成功的输出。

批量尺寸可保留各来源原尺寸，或显式应用同一最终宽高；草稿不参与启动，无效或超预算输入保留已应用值和已有结果。指定宽高可能改变比例，旋转也不交换这两个目标值。

批量续跑已接后继源码、待编译及回归：首次完成后，主按钮变为“重试未成功项”，只处理失败、取消和未开始项，全部成功时禁用。复用同一冻结计划及效果，保留原输入索引、命名时间、完整原片保护列表和成功记录，进度及最终结果都按原索引合并；已成功文件继续可复制路径，不再次写入。曾缺失的来源会重新检查本地可用性，修复文件后可重试；没有自动重试循环，每次点击独立累计该次尝试的像素预算。来源、目录或已应用参数实际变化才清除续跑计划；重复选择同值或钳制后不变的参数保留已有结果。

批量 PNG 可选择快速、均衡、最小压缩档位，WebP 则沿用单图的独立无损/有损模式和质量参数；选择在启动时与其它编码参数一起冻结，保存期间不能改变，同值或质量钳制后无变化的点击保留已有结果。

文字水印默认关闭，在颜色调整及可选锐化后的最终尺寸上自动平铺，复用已有 Scene 字体、倾角和 alpha 合成；原片保持只读，不额外生成整幅透明叠图。文字、字号、RGB 和不透明度在访问各项前统一校验。GDI 绘制和字体锁等待不能中途打断，取消在阶段前后响应并丢弃当前工作帧；覆盖透明像素处可以按既有合成规则增加 alpha，未覆盖像素保持不变。

## 图片转 PDF

PDF 输出使用普通 PDF 1.4 图像页，无脚本、外部资源或交互内容。A4 横竖页居中等比适配；原尺寸页按明确 DPI 计算，边距使用毫米。原图直通 RGB，透明部分白底合成，所有图像顺序与列表一致。

当前结果入口共享不可变处理快照，保留本次变换及动画当前帧，不重读已移动的父源。快照可与后续添加的磁盘图片混排、上下移动或移除；按文件排序时快照在前，文件按名称排列。磁盘页仍在保存确认后读取首帧，所有页共同计入像素预算，原片保护使用全部父源的并集。

默认总输入 3200 万像素、输出 128 MiB、最多 128 页。生成前精确计算对象、流、交叉引用表及尾部总字节数；逐行生成并检查取消，按已有原子写事务提交。

`image_pdf_smoke_artifacts` 是默认忽略的样本生成测试，显式运行后在 `target/image-pdf-smoke/` 写入三份双页 PDF 和两张参考 PNG，供独立阅读器验证页序、方向、边距、白底透明和颜色。结构单测不能代替阅读器回读与渲染。

## 像素取色与测量

取色读当前变换结果的原始 BGRA，不读缩略图或屏幕合成色，也不包含 JPEG 编码损失。RGB 与 alpha 分开显示，可保留和复制最近八个样本。

颜色格式支持 HEX、RGB、HSL、HSV 双向转换，按 8 位编码 RGB 换算；灰色的色相统一为零。透明颜色在 HEX 后附 alpha，或使用 rgba/hsla/hsva，复制单色和整组采样调色板都保留 alpha。手输草稿显式转换后才替换结果，非法输入保留旧色；图像取样也可直接填入转换框，颜色转换不改写图片。

两点距离使用图像物理像素，左上为 `(0,0)`，向右为 0°、向下为 90°；重合点没有方向。绘图、命中和标记共用源图宽高比计算的实际内容矩形，留白不钳制成图像边缘；辅助线只进入窗口渲染。

可见标尺在图像上方显示 X、左侧显示 Y 源像素索引，1/2/5 步距按窗口尺度选择，最多 32 项并保留首末像素刻度。刻度落在与取样相同的像素中心；标尺条和留白不可采样，隐藏标尺也不改变测量值或图像。过近标签可省略，刻度仍保留；标尺与点线都不进入导出。

## 二维码生成

生成复用现有二维码编码依赖，按整数模块倍数产生黑白像素，四模块静区始终保留。非 ASCII 文本显式使用 UTF-8 ECI 和 Byte 段，避免自动分段的字符集歧义。文本先受 UTF-8 字节预算限制，实际容量由编码器判定；ECI 和段头也占容量。成品颜色不跟随主题，窗口跟随主题；预览采用最近邻缩小。

复制图像时在后台准备剪贴板数据，发布前核对来源代次和剪贴板序号，准备期间用户已复制其它内容时不覆盖。另存通过共享快照进入图片工具，复用同一份像素和既有新文件保存流程。

## 一维条码识别

固定 `rxing 0.9.3`，关闭默认特性，仅启 `decoders`、`oned`、`encoding_rs`；字符集后端是此组合的必要特性。它采用 Apache-2.0、要求 Rust 1.85，不引入原生条码运行库，已经接入协调构建。[版本清单](https://github.com/rxing-core/rxing/blob/v0.9.3/Cargo.toml)、[字符集约束](https://github.com/rxing-core/rxing/blob/v0.9.3/src/common/character_set.rs)

内部窗口只读当前处理快照，可逐项选择 Code 128、普通 Code 39、EAN-13、EAN-8、UPC-A、UPC-E、ITF，反色默认关闭。扫描使用一张白底合成的灰度图，分别访问横纵二值行并尝试正反方向；同一行在已找到的端点两侧继续分段，完全相同的相邻二值行复用解码候选。同内容的不同位置分别保留，连续命中才合并为一条代表线，空白行打断合并。

位置严格限定为源像素扫描线和两个端点，不推测完整包围框，不把留白钳制成图像边缘。固定版本的 Code 39 停止点需要在当前二值行回数九个实际条纹恢复中心，再做裁块偏移和方向映射；恢复失败或端点无效就跳过候选。预览与标记共用实际绘制矩形，标记不进入输出。[固定版本 Code 39 读取器](https://github.com/rxing-core/rxing/blob/v0.9.3/src/oned/code_39_reader.rs)

默认单图 3200 万像素、累计采样 1.6 亿像素、解码 16384 次、128 个结果、单项文字 64 KiB、总文字 1 MiB、扫描时间 5 秒；临时工作集独立限 128 MiB。采样包括灰度生成和每次横纵二值行访问，完整正色为输入的三倍，含反色为五倍。每行、分段及调库前后检查取消，单次库内解码不能中断；取消或达到预算返回已有结果及明确终态。

窗口使用一个后台槽，选项在扫描期间锁定；进度只有一个最新值槽，关闭等待后台归还。列表按页显示，摘要转义控制字符并限制长度，复制保留完整原文及同内容的多个结果；含零字符的内容在写入前明确拒绝，保留原剪贴板，避免系统文本格式截断后仍报成功。[系统文本格式](https://learn.microsoft.com/en-us/windows/win32/dataxchg/standard-clipboard-formats)

七种固定样本、UPC-A 规范化、左右和上下双码、Code 39 宽留白定位、正反横纵、反色、错误校验、透明、取消和预算已有定向回归，并进入协调检查范围；可选 Code 39 校验位和任意 ITF 长度不在首批承诺范围。
