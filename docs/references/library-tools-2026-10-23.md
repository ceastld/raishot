# 工具并入图库：先有内容，后有工具（10-23 方案）

状态：第 8 节三项按推荐拍板（10-23）；P1 已进源码，见第 9 节；P2 的“合窗”部分已进源码，见第 10 节。原型 [design/library-tools.html](../design/library-tools.html)（深色优先、跟随系统，用自己的浏览器打开）。取代 [整体优化计划](media-viewers-recording-tools-plan-2026-10-22.md) T01 的“工具页”入口形态；T02–T10 的算法与工具视图不变，只改它们从哪里拿来源、在哪里打开。

## 1. 现在为什么割裂

| 现象 | 根因 |
| --- | --- |
| 主界面“工具”页 10 张卡片，点任何一张都是“开新窗口 → 弹文件框” | 工具按**实现**排成入口，不知道用户手里有什么；截图库就在隔壁一页，工具却让人去资源管理器里找刚截的图 |
| 同一工具三处入口三种行为：查看器工具栏从当前像素进；历史详情只有查看／编辑；工具页走文件框 | 没有统一的工具注册与来源模型，每个入口自己拼参数 |
| 对照、拼接、PDF、分割、测量、条码各是独立顶层窗口 | 工具视图都自建 `WindowHandle`；关闭、焦点、主题、任务栏各自为政，主界面只是个启动器 |
| 卡片没有状态：不知道哪个工具适用、需要几张图 | 适用条件（几张、图片还是录屏）写死在描述文字里 |

一句话：**工具页是个文件启动器，不是工作流。** 截图工具的工具，来源天然就是刚截的图。

## 2. 原则

1. **先有内容，后有工具。** 工具是“对选中内容的动作”，不是一个入口页。选中一张、两张、一段录屏，界面告诉你能做什么。
2. **一处注册，处处出现。** 一个工具注册表，按选区推断“可用／还差什么”；图库操作条、右键菜单、查看器“工具”菜单、贴图右键都从它取，行为一致。
3. **不离开主窗。** 工具在主窗弹层中打开（推广已有的媒体弹层），Esc 回到原选区和滚动位置。
4. **文件框只是兜底。** 外部图片拖进主窗或 Ctrl+O，变成图库里的临时条目并被选中，然后走完全同一条路。

## 4. 工具注册表

纯模型，GPUI 只渲染。每个工具声明接受的类型与数量，选区摘要（图片数、录屏数）进来，得到 `Ready` 或 `Need(提示)`。

| 工具 | 接受 | 打开方式 | 产出 |
| --- | --- | --- | --- |
| 查看 | 1 图／1 录屏 | 弹层（已有） | — |
| 贴出 | 1–N 图 | 直接执行 | 屏幕上的贴图 |
| 编辑 | 1 图 | 编辑器（已有） | — |
| 识别文字 | 1 图 | 直接执行，结果进详情栏 | 文字 |
| 对照 | 恰好 2 图 | 弹层 | — |
| 拼接 | 2–N 图 | 弹层 | 新图 |
| 转 PDF | 1–N 图 | 弹层 | PDF |
| 批量导出（格式／尺寸／水印） | 1–N 图 | 弹层 | 文件夹 |
| 分割 | 1 图 | 弹层 | 多图 |
| 取色与测量 | 1 图 | 弹层 | — |
| 识别条码 | 1 图 | 弹层 | 文字 |
| 转 GIF | 1 录屏 | 弹层 | GIF |
| 生成二维码 | 无来源 | “新建”菜单 → 弹层 | 新图 |

混合选区（图片＋录屏）时，图片工具只作用于其中的图片，按钮上写明“3 张图片”；录屏工具要求只选一段。

**推荐动作**（操作条上直接露出的 2–3 个，其余在“工具 ▾”里）：

| 选区 | 推荐 |
| --- | --- |
| 1 张图 | 贴出 · 编辑 · 识别文字 |
| 2 张图 | 对照 · 拼接 |
| 3 张以上 | 拼接 · 转 PDF · 批量导出 |
| 1 段录屏 | 播放 · 转 GIF |
| 混合 | 导出到文件夹 · 删除 |

## 5. 交互

### 5.1 内容先行（主路径）

- 单击选中，Ctrl／Shift 多选，Ctrl+A 全选，空白处框选（框选可放 P2）。
- 单选：右侧详情栏顶部出推荐动作 + “工具 ▾”。
- 多选：底部浮出操作条：`已选 3 张  [拼接] [转 PDF] [批量导出]  工具 ▾  ·  复制 删除  ✕`。Esc 清空选区。
- 右键菜单 = 同一套推荐 + 工具子菜单。

### 5.2 工具先行（选择模式）

图库顶栏有“工具 ▾”按钮，菜单列出全部工具，适用的直接可点，不适用的写出还差什么（“选 2 张图片”）。点一个不适用的工具：

- 图库进入选择模式：卡片出现勾选框，类型筛选自动切到工具接受的类型；
- 顶部横幅：`对照 · 选择 2 张图片   已选 1/2   [取消] [开始]`；
- 已选够时“开始”变主按钮，Enter 开始；Esc 退出选择模式，原选区恢复。

这样“我想拼图”的人和“我手里有几张图”的人走到同一个地方，且都不经过文件框。

### 5.3 工具弹层

主窗内全区弹层（与媒体弹层同一宿主），三段式：

```
← 图库   拼接                       [复制] [贴出] [另存为…]
来源条：[图1][图2][图3] [+ 添加]          ← 可拖动排序、悬停移除
───────────────────────────────────────────────
             预览                 │ 选项（方向、间距、背景…）
```

- **来源条**：多图工具的顺序就在这里拖；“+ 添加”把弹层收起成选择模式回到图库挑，挑完回来，不弹文件框；菜单次项“从文件…”。
- **统一产出栏**：所有产出图片的工具右上角同三件事——复制、贴出、另存为；产出文件夹的工具是“导出到…”。保存后提示带“在文件夹中显示”。
- 单图工具之间可在弹层标题处切换（测量 → 分割 → 条码），不关弹层、不重读源图。查看器里的“工具”菜单也打开同一弹层，而不是另起窗口。
- 弹层打开期间主窗其它页面不可交互；切页或关窗释放工具会话（沿用媒体弹层的释放规则）。

### 5.4 外部文件

- 把图片／视频拖进主窗任意位置：图库顶部出现“外部文件”分段（仅本次窗口生命周期，不写历史、不复制文件），这些条目被选中，操作条随之出现。
- Ctrl+O、工具菜单底部“打开文件…”同理。没有截图历史时，图库空状态给出“拖入图片或打开文件”。

### 5.5 新建

图库顶栏“新建 ▾”：截图、录屏、从剪贴板贴图、二维码。二维码是唯一无来源的工具，放在这里而不是混在“对选区的动作”里。

## 6. 实现要点

- **`tool_registry.rs`（新，纯模型）**：`ToolId`、`Accepts { kind, min, max }`、`fn availability(tool, &SelectionSummary) -> Availability`、`fn recommended(&SelectionSummary) -> Vec<ToolId>`、标签与图标；配过滤测试（`tool_registry_`）。
- **图库选区**：`HistoryPage.selected: Option<String>` 改为有序 `Vec<String>` + `anchor`，保持“选中顺序”作为拼接／PDF 默认顺序；单选详情栏行为不变。
- **工具弹层**：`MediaPopup` 推广为 `ToolPopup`，`Content` 增加各工具实体；工具视图拆成“可嵌入的实体 + 可选的独立窗口外壳”，现有 `open*()` 只剩查看器之外的过渡调用。弹层负责标题、来源条、产出栏；工具视图只渲染预览和选项。
- **来源**：统一 `ToolSource { key, path | pin_record, kind }`，解码沿用 `image_decode` 前台预算与取消；不再有 `ToolsPage.loading/cancel` 这种页面级读取状态。
- **退役**：`main_tools.rs`、`MainPage::Tools`（解析与 wire 保留映射到图库）、各工具空来源时的文件框路径。

## 10. P2 合窗（10-25）

- 宿主 `tool_host.rs`（`image_tool_view::host`）：工具视图不再自建窗口，构造函数接 `ToolHost::Window | Popup`；关闭统一走 `finish_close`（窗口移除自身，弹层发 `ToolCloseRequested`），系统标题只在独立窗口里改。九个工具视图（对照、拼接、转 PDF、批量导出、分割、取色与测量、识别条码、二维码、图片处理）都已接入。
- 图库弹层 `main_tool_popup.rs`：图库里打开的工具（含“工具”菜单底部的生成二维码）都在主窗口内全区弹出，顶栏“‹ 图库 / 工具名”与“关闭 · Esc”；点遮罩不关闭，避免丢参数。关闭先走工具自己的取消流程，后台任务归还后才收起，期间顶栏提示“正在取消，完成后关闭…”；收起后焦点回到原选区。切页时同样请求关闭。同一时间只有一个工具弹层，新工具打开前先请求旧的关闭，旧工具还在处理就保留并在状态栏提示。
- 独立窗口复用：查看器“图片处理”、它的“用结果继续”和 `--open-tool` 仍开独立窗口；同一工具已有空闲窗口时在原窗口里换上新内容（`replace_root`，位置大小不变）并提到最前，原窗口正在处理时另开一个，不打断它。
- 验证：隔离数据目录（`RUSTSHOT_DATA_DIR` 指向放了合成截图的 QA 目录）下用投递点击走通“工具 → 对照／分割／拼接 → 勾选 → 开始”，进程始终只有主窗口一个顶层窗口；Esc 回到图库且原选区保留；查看器两次点“图片处理”窗口数不变且内容重置；独立窗口 Esc 照常关闭并退出。真实鼠标拖动排序、保存对话框在弹层里的表现未验。
- 来源条、回图库挑图与单图互切见第 11 节；外部图片进图库见第 12 节；“新建”菜单见第 13 节。

## 11. 来源条与单图互切（10-25）

- 来源条 `tool_source_strip.rs`（`image_tool_view::strip`）：拼接和转 PDF 的来源改成缩略图格（序号、名称，悬停显示移除），拖到某格上插在它前面，拖到末尾“添加”格上移到最后；缩略图按路径后台有界解码一次并缓存。批量导出最多 4096 张，保留分页列表，但每行加小缩略图、整行可拖动排序，上下箭头按钮去掉。拖放只认同一视图发起的拖动。
- 回图库挑图：弹层里的“从图库添加”（拼接、转 PDF、批量导出）和对照的“换图片…”发 `ToolEvent::PickSources`。宿主收起弹层（工具实体和参数保留），图库进入该工具的选择模式并按当前来源预先勾选，焦点交给图库；横幅主按钮写“完成 Enter”。完成后来源按挑选顺序交回工具（`HostedTool::set_sources`），不在图库里的外部文件接在后面；Esc 取消则原样展开。转 PDF 的“当前结果”快照页保留在最前。独立窗口里同一按钮仍弹文件框，侧栏“最近截图”只在独立窗口显示。
- 单图互切：分割、取色与测量、识别条码在弹层顶栏显示三段切换，共用图库后台解码好的 `Arc<Image>`，切换不重读文件；当前工具在处理时不切，状态栏提示。
- 独立窗口同样互切（10-25）：查看器“图片处理”的“用结果继续”和 `--open-tool split|measure|barcode` 打开同一个单图工具窗（`tool_single_window.rs`，`image_tool_view::single`），顶栏三段切换，共用图片处理的当前产物（含未保存调整）或解码好的像素，切换只换窗口里的工具视图。三个工具按“单图工具”整体复用一个窗口；当前工具在处理时切换栏置灰并提示。关闭仍交给当前工具：先取消后台任务，再移除窗口。
- 验证：隔离数据目录下投递点击与拖动走通拼接“从图库添加 → 勾第三张 → 完成”（3 张，预览重算）、拖第三格到最前、PDF 页格、批量行拖动、对照“换图片…”预选两张、分割 → 取色与测量 → 识别条码互切；修正了收起弹层后 Esc／Enter 落在隐藏工具上的问题。真实鼠标拖动手感、外部文件混排后的回填顺序未验。

## 12. 外部图片进图库（10-25）

- 入口：把图片拖进主窗口任意位置（主窗口正文 `on_drop`，图库网格在拖过时变色提示），或 Ctrl+O／“工具”菜单的“加入图片文件…”（可多选）。不在图库页时先切过去；工具或媒体弹层的遮罩会挡住下层命中，预期不会触发（未实测）。
- 模型：`library::Source::File`，键为 `file:` + 小写路径，重复加入同一文件只换成新读到的版本。条目只存在于本次窗口（`HistoryPage.external`，始终排在 `items` 开头），重扫历史时接回最前，不写历史、不进索引、不复制文件。
- 加入：后台按真实格式逐张解码一次（`library::external_item`，与截图缩略图共用解码闸门、工具的像素上限），得到原图尺寸和缩略图；读不出来的不进图库，状态栏写明第一个失败原因。一次最多 200 张；非图片文件跳过并计数；只拖进一段视频时交给内置播放器。
- 加入后：图库顶部单独一组“外部文件 · 仅本次显示，不写入图库”，筛选切回“全部”、清空搜索、滚到顶，新图按拖入顺序全部选中，操作条随即给出推荐工具；正在选择模式时直接勾上（受张数上限）。
- 行为与截图一致：贴出、复制图片、编辑、查看、在文件夹中显示和全部图片工具；卡片角标“外部”。删除改为“从图库移除（不删文件）”，同样可撤销，到期只把它从列表拿掉。
- 顺带修正窄窗口布局：图库工具栏右侧一组放不下时整体换到第二行，详情栏可见时底部操作条不再重复“已选 N 项”和说明（详情栏已列出），说明在窄处缩成省略号，不再压到详情栏或被裁掉左边。外部条目的撤销提示写“已从图库移除 N 项（文件未删）”。
- 验证：`cargo test --lib library_` 含外部条目尺寸、标题、大小写去重、移除不删文件、缺失文件报错；隔离数据目录下用“加入图片文件…”多选 PNG／JPEG／WebP 和一个 txt，走通分组、选择顺序、操作条。拖放走 OLE，投递消息模拟不了，真实拖入未验。

## 13. 图库“新建”菜单（10-25）

- 图库顶栏“工具 ▾”左边加“新建 ▾”（`main_history_new.rs`），放往图库里添内容的入口：区域截图、截取当前屏幕、录屏、从剪贴板贴图，分隔线后是生成二维码和加入图片文件（Ctrl+O）。“工具”菜单只留对已选内容的动作和“打开视频文件…”，二维码和加入图片文件从那里移过来。两个菜单共用一个展开状态和同一套外框（`menu_panel`／`menu_item`／`history_menu_slot`）。
- 截图类请求由托盘常驻进程执行：主窗口先最小化，等 300ms 动画结束再向托盘窗口投递截图消息（与托盘菜单“区域截图／当前屏幕”同参数），并允许托盘切到前台。剪贴板贴图投递托盘的剪贴板贴图命令，稍后重扫图库。托盘没在运行时状态栏说明，不最小化。
- 录屏没有单独的启动入口：菜单项开始区域截图，提示“框选后按 G”。做成直接进入录屏模式要改截图视图，暂不做。
- 主窗口在截图后保持最小化。图库页在主窗口重新激活时补一次过期重扫（距上次超过 10 秒），所以“新建”或快捷键完成的截图回到主窗口就能看到。
- 验证：隔离数据目录下菜单展开、二维码弹层、加入图片文件走通。截图和剪贴板贴图会作用到本机正在运行的托盘和真实桌面，未在自动测试里点。

## 14. “编辑”改为贴出即编辑（10-25）

- 反馈：图库“编辑”另开一个图片编辑窗口，窗口里再浮一条截图工具栏，层次多、像在窗口里截图，很别扭；而贴图本身就能完整标注、对象编辑和撤销。
- 现在图库“编辑”（操作条、详情栏、`Request::PinEditFile`）和查看器“编辑标注 · E”都改为：在鼠标处贴出图片，约 120ms 后（贴图首次显示、工具栏子窗能按宿主矩形定位）自动展开贴图工具栏，直接在贴图上原位标注。托盘入口 `--pin-edit-file <路径>`，`pin_app::open_editing` 共用。
- 独立图片编辑窗口保留给需要大块停靠区域的场景：长截图剪辑、截图翻译结果、查看器的裁剪与 OCR、命令行 `--edit-file`。
- 曾考虑把编辑器嵌进主窗口弹层：`CaptureView` 以整窗为坐标原点（事件位置、`viewport_size`、鼠标捕获、原生子窗定位约百处），嵌入需要统一加宿主偏移，改动面大，暂不做。
- 验证：`cargo test --lib tray_request`、`file_launch_command` 通过；隔离数据目录下实际运行 `--pin-edit-file`，贴图、标注工具栏和属性栏三个窗口都出现，没有编辑窗口。图库按钮经托盘转发，托盘需换成新版才认 `pin-edit-file`，经托盘的整条路径与查看器 E 未在真实界面点过。
