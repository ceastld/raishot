# 快捷键系统设计（2026-10-27）

状态：首批 13 项命令已接入源码，编译检查与过滤测试通过。优先解决适合全局触发的高频操作，再逐步统一截图、贴图编辑器内的快捷键。

## 1. 用户能得到什么

设置 → 快捷键按分类列出可绑定的**操作**，不再只有“截图”“剪贴板贴图”两个固定入口。点击右侧快捷键框录制，清除即可停用；托盘对应菜单项显示配置的绑定。

操作选择原则：高频、可以从任意应用触发、目标明确；需要挑选文件的操作可以打开选择器。依赖当前选区、当前文字或正在编辑对象的操作属于会话内快捷键。删除、清空、关闭全部、退出应用等影响较大的操作暂不纳入全局目录。

首批 13 项，只有原有两项保留默认键，其余默认未绑定：

| 操作 | 行为 | 新安装的默认绑定 |
| --- | --- | --- |
| 截图 | 沿用现有截图入口及默认截图配方 | Ctrl+1 |
| 当前屏幕截图 | 截取鼠标所在屏幕并进入编辑 | 未设置 |
| 所有屏幕截图 | 截取全部屏幕并进入编辑 | 未设置 |
| 剪贴板贴图 | 图片优先，否则贴纯文本 | Ctrl+2 |
| 打开图片贴图 | 打开本地图片选择器，选图后贴到屏幕 | 未设置 |
| 显示／隐藏当前分组贴图 | 当前组只要有一张未隐藏就全部隐藏；全部隐藏则全部显示 | 未设置 |
| 恢复最近关闭的贴图 | 沿用已有恢复入口 | 未设置 |
| 上一个贴图分组 | 按分组顺序循环切换 | 未设置 |
| 下一个贴图分组 | 按分组顺序循环切换 | 未设置 |
| 恢复贴图交互 | 显示贴图并关闭穿透，保留旧未分组窗口的兼容处理 | 未设置 |
| 管理贴图 | 打开主窗口贴图页 | 未设置 |
| 打开图库 | 打开主窗口图库页 | 未设置 |
| 打开设置 | 打开设置页 | 未设置 |

按用户确认，快捷键列表只提供这一个切换动作，不拆成隐藏、显示两个可绑定项。同一快捷键每次按下切换一次。新增命令不自动抢占用户按键。升级使用用户原配置，不能以新安装默认值覆盖已改键或已停用的项。

OCR、翻译、复制、快速保存、当前窗口／上次区域采集继续由已有快捷动作组合，不再增加重复的固定命令。录屏启停、长截图控制以及标注工具选择依赖会话状态，保留各自的局部快捷键，待单独明确上下文后扩展。

## 2. “当前分组”的准确含义

- 指主窗口贴图页／托盘正在使用的 `Workspace.current_group`，不是鼠标所在贴图或最近获得焦点的窗口所属分组。执行时读取，不把分组 ID 固化到快捷键。
- 目标必须同时满足：属于本托盘实例创建的进程、有对应实时窗口、工作区状态为 `Active`、属于当前组。其它分组、其它实例和已关闭记录不参与。
- 显示不恢复已关闭贴图、不补开丢失窗口、不抢前台焦点，不更改位置、大小、标注、锁定或鼠标穿透。
- 沿用现有隐藏状态的持久化语义。首版不另建临时“整组遮罩”，因此显示会解除本组各张贴图的隐藏状态，不记忆隐藏前的混合显隐分布。
- 切换按上述有效目标的 `hidden` 状态决定方向，不用窗口是否被遮挡作为依据。空组不切换任何状态；连续按住只执行一次，松开后再按才执行下一次。
- 正常完成保持安静；无目标时只给简短且限频的“当前分组没有打开的贴图”提示；写入失败显示具体原因，不能宣称整组已完成。

现有 `pin_workspace_runtime::manage` 已有大部分筛选，但逐张调用 `SetHidden`，可能部分成功。接入时增加批量显隐入口：在工作区锁内固定当前组和合格目标，判断切换方向并整批提交隐藏状态，再广播窗口同步，避免连续触发读到同一个旧状态。状态提交成功不等于每个窗口已经绘制完成；运行时窗口退出仍须容忍。

现有 `pin_native::manage` 还处理没有工作区标记的旧窗口，它们没有可靠分组归属。新分组命令只操作已登记工作区的窗口；托盘原有隐藏／显示两项合并为同一个切换项，名称与快捷键列表一致，使用相同入口，不能通过兼容回退影响无分组窗口。底层可保留设为显示／隐藏的实现函数，但不作为两个用户动作。旧窗口的其它管理入口保留，未来登记迁移另行处理。

## 3. 设置页

第一版展示全局命令，分类为“截图”“贴图与分组”“应用”“快捷动作”。首批数量有限，直接分区展示；搜索和“仅看已设置”留到目录扩大后再加。截图、贴图编辑器内的局部快捷键保留现有行为与帮助入口，后续再开放自定义。

每行包含：操作名、短说明、快捷键录制框、恢复默认按钮。无绑定的框显示“未设置”；清除即停用。恢复默认指该操作的默认绑定，新增项恢复后仍为未设置。

贴图与分组区域示例：

| 操作 | 说明 | 快捷键 |
| --- | --- | --- |
| 显示／隐藏当前分组贴图 | 有显示的贴图时隐藏，否则全部显示 | 未设置 |

沿用现有录制手势：按下组合并全部松开后提交；Esc 取消、Backspace 清除、鼠标单击退出录制。13 个固定命令均支持系统组合键及已有键盘／鼠标组合。快捷动作的配方与绑定编辑保留原入口，目前只接受系统热键，但加入统一冲突检查。

状态至少区分“正在录制”“正在应用”“已生效”“与某操作冲突”“被其它程序占用”“已保存，等待托盘启动”。失败行显示实际仍生效的旧绑定；不得仅凭文件保存成功显示“已生效”。所有文案使用现有中英翻译机制，布局与配色跟随应用主题。

## 4. 命令、绑定、执行分开

| 概念 | 内容 | 责任 |
| --- | --- | --- |
| 命令目录 `HotkeyTarget::ALL` | 稳定 ID、名称、说明、分类及默认绑定 | 统一注册、设置页与托盘操作；新命令不增加平铺偏好字段 |
| `Binding` | 命令 ID 与一个可选 `Trigger` | 首版每条命令一个绑定，清除与恢复默认是不同操作 |
| `Trigger` | 现有 `Hotkey(HotkeySpec)` 或 `Input(InputTrigger)` | 沿用录制、归类、键帽和序列化规则 |
| 命令分派 | 命令 ID → 截图／贴图／应用处理函数 | 托盘菜单与快捷键共享业务路径 |
| 生效状态 | 全目录请求签名、请求时间、托盘身份与错误 | 由托盘返回，设置页校验当前请求后回读 |

快捷动作保留自己的稳定动作 ID 和配方，运行时仍调用原 `QuickRecipe`，其绑定参加同一冲突检查。分组动作不塞入截图配方，以免无意启动截图／GPU 会话。

固定命令的全局注册、监听、暂停／恢复、回执和冲突检查统一遍历目录；快捷动作保留现有注册槽位并一同暂停／恢复。现有 `HotkeyTarget` 承担命令目录，不另外建立重复的枚举。

常驻进程负责注册和分派；分组显隐直接走工作区操作，不启动额外 GPUI 进程，也不改变现有待命进程模型。只有需要交互的新窗口才沿用相应前台授权流程。

## 5. 配置与升级

首版沿用 `settings.json`：旧截图／剪贴板字段保持兼容，新命令放在一个 `command_hotkeys` 对象内，复用 `config_json` 的锁、原子写入和损坏备份。快捷动作仍存 `quick_actions.json`，本轮不引入跨文件迁移。新命令示例：

```json
{
  "schema_version": 1,
  "command_hotkeys": {
    "pin.group.toggle_visibility": {"mode": 6, "modifiers": 1, "key": 49, "trigger": "key:14 + key:48"}
  }
}
```

- 模式 3 为系统热键、4 为停用、6 为键盘／鼠标组合。新命令缺失时未绑定，清除后保留录制内容但不注册；恢复默认也是未绑定。
- 旧两项的预设、自定义键、输入组合与禁用值原样读取。新增命令不继承 Ctrl+1，也不为旧配置重设默认。
- 保存单个快捷键时在锁内重读，只更新目标字段，保留其它命令、未知命令和其它设置（含 API 密文）。录制操作不重新加密或改写其它配置。
- 未知命令原样保留但不执行；损坏的新命令绑定停用，不回退成截图键。
- 注册失败的回写也在同一锁内逐项比较请求值；若用户已改过同项则跳过过期回写。
- 快捷动作保留其现有存储与启用规则。本轮不改动配方、动作 ID 或已有快捷动作绑定格式。

## 6. 冲突、失败与录制

1. 保存前把内置命令与已启用快捷动作放入同一份冲突检查。系统热键检查重复，输入组合检查重复与前缀冲突；系统键与监听组合也要检查按键重叠是否会造成输入被消费，不仅比较两个后端内部。
2. 冲突提示明确列出操作名和组合，第一版直接拒绝新绑定并保留原绑定。暂不提供自动替换其它操作，避免引入多命令交换事务。
3. 系统注册沿用先取得新组合、再释放旧组合。跨系统热键／输入监听切换须能回滚；若回滚也失败，如实返回“当前未生效”，不能把配置值当成实际绑定。
4. 录制期间暂停全部全局绑定，包括快捷动作。取消、失焦、页面关闭和录制进程异常退出均恢复；保留现有录制属主与超时恢复机制。
5. 回执签名覆盖整个命令目录及停用时保留的组合；配合请求时间和托盘身份拒绝旧回执。失败后只有磁盘值仍等于失败请求时才回写实际可用值，避免覆盖其它设置窗口的新修改。
6. 未启动托盘时可保存，明确标记等待生效；托盘启动后逐条注册并报告实际失败。被系统或其它程序占用的组合不承诺一定可用。
7. `WM_HOTKEY` 的分配仍限制在应用可用的 ID 区间。固定目录在低半区按命令分配轮换区间，16 个快捷动作保留 `0x8000..0xbfff`。保留旧消息校验及安全复用策略；输入监听事件也携带绑定代次，改键与录制恢复后拒绝过期命中。

## 7. 分步实施与验收

第一步完成 13 项命令目录与通用绑定表，扩展固定命令注册／冲突／回执管线，证明原有绑定与禁用值完整保留。

第二步接入首批所有命令，包括“显示／隐藏当前分组贴图”、上一组／下一组；托盘合并显隐项并共用执行入口，设置页按分类显示。

第三步再设计局部工具快捷键、录屏／长截图等有上下文要求的操作。第一、二步不依赖第三步。

实施时的最小验证：

- 模型与配置：旧模式保留、新命令默认停用、未知命令保留、单项更新不覆盖其它项、所有绑定来源的冲突与前缀冲突。
- 运行时：注册失败保留旧绑定，跨后端失败回滚，迟到回执不覆盖新值，录制暂停与恢复全目录，旧热键事件不误执行新命令。
- 分组：两组混合显隐、全隐藏、空组、已关闭记录、其它实例、无工作区标记窗口；按住不连续切换，松开再按反向切换，连续请求按提交后的状态判断，批量保存失败不报告整组成功。
- 按仓库规范在主 `target/` 做最小 `cargo check` 与受影响模块过滤测试。需要实窗验证时再 Dev build，更新运行副本并检查录制、隐藏后全局显示及托盘标签。未完成的真实交互单独说明。

验证：`cargo check` 通过；`cargo test --lib hotkey` 的 25 项通过，复用同一测试程序补跑触发器、分组与命令路由筛选的 20 项通过（跳过首批已执行项）。覆盖旧值兼容、锁内保存和迟到回滚、跨后端冲突、部分注册失败后的再校验、空组与混合显隐、循环边界。`cargo build --bins` 通过，三个 Dev 程序已更新到运行副本并重启；实窗确认深色设置页、分类、原绑定及单一分组显隐项显示正常。真实物理按键、侧键和多实例窗口交互仍未验证。
