# 主界面：贴图、历史、录屏与设置合一（10-19 方案）

状态：五项已按推荐拍板（10-19）；M0 外壳已进源码，见第 11 节。原型 [design/main-window.html](../design/main-window.html)（深色优先、跟随系统主题，用自己的浏览器直接打开）。

## 1. 现状问题

| 窗口 | 进程 | 问题 |
| --- | --- | --- |
| 设置 | 辅助进程 `--settings`，单实例 | 本身尚可；但只是“设置”，没有承载内容 |
| 截图历史 | 辅助进程 `--history`，独立窗口 | 只认文件名／UTC 日期／尺寸；默认关闭；Enter 贴图、Delete 删除；和贴图、录屏毫无关系 |
| 贴图工作区 | 贴图宿主 `--pin-workspace`，独立窗口 | 后台管理表单：纯文字列表无缩略图；标题要“应用／还原”；分组靠“↑上移／↓下移”；活动与已关闭两张列表；“解除锁定／解除穿透”只能单向；整段说明文字堆在页面里 |
| 录屏历史 | 录屏会话进程内打开 | 文件名列表，UTC，无缩略图、无删除；窗口挂在 GPU 会话进程上，延长会话寿命 |

根问题不是样式，而是**按实现拆窗口**：同一件事——“我刚截／贴／录的东西在哪”——被拆成历史目录、已关闭贴图（20 条／7 天）、工作区清单、录屏目录四套存储、四套保留规则、四个入口。关闭的贴图和截图历史是两份几乎相同的东西，却各有上限。

## 2. 设计原则

1. **一个窗口，一条时间线。** 主界面就是现在的设置窗口升级：左侧导航上半是内容（贴图、历史、收藏），下半是设置。托盘、录屏预览、贴图右键都只是“打开主界面的某一页”。
2. **以图找图。** 所有条目都以缩略图出现；时间用本地时间和“今天／昨天／周一”分段；文件名不是主信息。
3. **直接操作，不要表单。** 标题 F2 原地改、Enter 生效 Esc 放弃；分组拖动排序；锁定／穿透／隐藏是图标开关；删除立即生效、底部可撤销，不弹确认。
4. **状态说清楚，说明文字不进正文。** “在屏幕上”“已隐藏”“在屏幕外”“已关闭”用徽标表达；规则放到悬停提示或设置页。
5. **主界面不是会话。** 主界面只读写存储并发控制请求，不托管贴图、不挂在截图／录屏 GPU 会话上；关掉主界面不影响任何贴图。

## 3. 信息架构

```
RaiShot 主界面
├─ 贴图（N）      屏幕上的贴图：显示器布局图 + 分组 + 列表
├─ 历史           所有截图／贴图／录屏的统一时间线（类型筛选）
├─ 收藏           打星的条目，不受保留期清理
└─ 设置 ▾         常规 · 截图 · 贴图 · 录屏 · 翻译 · 快捷键 · 保存 · 工具栏 · 历史与存储
```

- 导航宽 200，窄于 760 收成 56 的图标栏。设置分组展开时只展开子页，内容项始终可见。
- 顶部统一搜索（Ctrl+F）作用于当前页；`Ctrl+1/2/3` 切换内容页，`Ctrl+,` 打开设置。
- 窗口默认 1080×720、最小 720×480，记住位置与上次页面；单实例沿用现在设置窗口的发现机制。

## 4. 贴图页

上半是**显示器布局图**，下半是**当前分组的贴图列表**，分组用页签。

### 4.1 显示器布局图

- 按虚拟桌面物理像素等比缩放画出各显示器（主屏标记），每张贴图画成真实位置与尺寸的缩略图块；隐藏的贴图虚线框、半透明，其它分组的贴图不画。
- 单击块：列表同步选中，屏幕上该贴图闪一下边框并置前（“定位”）。双击：置前并激活。
- 拖动块：移动真实贴图到对应位置，可跨显示器；松开提交一次位置。
- 与所有显示器相交不足 20% 的贴图归为“在屏幕外”，在图边缘以箭头徽标显示，提供“调回”（移到鼠标所在屏中心）。这是现在完全缺失、又最常见的丢贴图场景。
- 布局图高度可拖，最小可收起成一条显示器缩略条。

### 4.2 分组

- 页签显示分组名和数量，当前分组（屏幕上正在显示的）有实心标记；单击页签 = 切换当前分组（与托盘一致），不再有“浏览分组”和“当前分组”两个概念。
- 页签拖动排序；双击或 F2 改名；右键：改名、颜色、删除（非空分组删除时贴图并入默认组，可撤销）。“＋”新建并直接进入改名。
- 贴图卡片拖到页签上 = 移到该分组。
- 分组颜色用于页签圆点和贴图标题条左侧色条（后续可选）。

### 4.3 贴图列表

每行：缩略图、标题（F2 原地改）、尺寸与缩放、来源时间，右侧三个开关图标——显示／隐藏、锁定、鼠标穿透——直接反映实时状态并可来回切换；悬停再出“定位”“关闭”。处理中／关闭中的贴图开关置灰并显示小转圈。

列表底部固定一条“最近关闭（n）”抽屉：横向缩略图，单击恢复、“全部恢复”。更早的关闭记录在历史页。

## 5. 历史页

### 5.1 条目

所有产出都是同一种条目，按创建时间倒序、按本地日期分段：

| 类型 | 缩略图徽标 | 双击／Enter | 主要动作 |
| --- | --- | --- | --- |
| 截图 | — | 贴出 | 复制、编辑、另存为、OCR |
| 贴图 | 绿点“屏幕上”／灰“已关闭” | 屏幕上：定位；已关闭：恢复原贴图（含标注与撤销栈） | 复制、恢复、移到分组 |
| 文字贴图 | “文” | 同贴图 | 复制文字 |
| 录屏 | 时长 `0:42`、`GIF` | 内置播放器打开 | 用系统应用打开、复制文件、转 GIF、在文件夹中显示 |

同一次截图既复制又贴出时只算一个条目，详情里列出它的去向（已复制、已保存到…、已贴出）。

### 5.2 布局与交互

- 顶部：搜索框 + 类型筛选片（全部／截图／贴图／录屏）+ 排序与缩略图大小滑块。
- 网格：固定行高的等高卡片，宽度按比例自适应（照片墙式），虚拟滚动；日期标题吸顶。
- 卡片悬停出三个快捷按钮（贴出、复制、更多）；右键完整菜单。
- 选择：单击选中，Ctrl／Shift 多选，空白处框选；多选时底部浮出操作条：收藏、导出到文件夹、移到分组、删除（复制只对单张）。
- 右侧详情栏（可收起，窄窗口变成抽屉）：大图预览、标题、本地时间、尺寸／大小、来源应用与窗口标题、去向列表（路径可点“在资源管理器中显示”）、已识别文字（可复制）、动作按钮。
- 空格：窗口内快速预览大图（左右键翻页，Esc 返回）；录屏在快速预览里直接播放。
- 拖出：卡片拖到其它应用即拖出 PNG／MP4 文件。
- 删除：立即从列表消失，底部“已删除 3 项 · 撤销”10 秒；超时后截图缓存真删，录屏文件进回收站（不硬删用户文件）。
- 历史关闭时：页面仍显示录屏和关闭的贴图，顶部一条“截图历史已关闭 · 开启”。

### 5.3 搜索

匹配标题、来源应用／窗口标题、本地日期（`10-19`、`昨天`）、尺寸（`1920x1080`）、已识别过的文字。只搜已有 OCR 结果，不为搜索后台跑 OCR。

## 6. 设置页的调整

- 设置页沿用现有页面实现，挪进主界面右栏；顶部标题与说明保留，底部状态栏改为主界面共用的提示条。
- 新增“历史与存储”页，收拢原“常规 ▸ 本机历史”和分散的保留规则：

  - 存储占用：历史、贴图工作区、录屏、OCR 模型分别显示大小，各有“打开文件夹”“清理”。
- 录屏选项若已有独立配置，单列“录屏”页（输出目录、默认格式、帧率、声音）。

## 7. 数据模型

管理数据使用 `pin-workspace\library.sqlite3`，图片与录屏继续存文件。贴图元数据、分组、文档与历史库索引共用一个 SQLite 文件：

```text
Item {
  id, kind: Shot | Pin | TextPin | Recording,
  created_ms, title, starred, deleted_ms?,
  source: { app?, window_title? },        // 截图时已知的前台／UIA 窗口
  size: (w, h), bytes,
  thumb: "thumbs/<id>.png",               // 最长边 320，截图完成时后台生成
  shot_file?: "history/shot-*.png",
  pin_id?: String,                        // 指向数据库中的贴图记录
  recording_file?: PathBuf,               // 用户录屏目录里的成片
  outputs: [Copied | Saved(path) | Pinned | Ocr],
  ocr_text?: String,
}
```

- `pin_meta` 保存修订号、当前组与恢复开关，`pin_groups`／`pin_items` 保存轻量列表数据，`pin_documents` 单独保存每张贴图的矢量文档与撤销重做。窗口位置、缩放、锁定与穿透更新只改对应元数据行，不读取或重写文档；主界面后台读取摘要，恢复及内容更新等操作仍沿完整文档校验。
- `catalog_items` 保存截图、贴图、录屏的统一索引及时间排序。每次历史扫描增量更新当前来源，只有成功完成扫描的来源才清除失效行；来源失败不会把旧索引重新变成可操作条目。贴图标题与状态仍以工作区记录和实时窗口为准。
- `catalog_recording_metadata` 按文件的卷、FileId、创建／修改时间、长度与属性缓存视频尺寸和时长；文件版本不符时重探测。图片与视频像素不进数据库，缩略图目前仍只缓存于内存；磁盘缩略图库、来源应用、去向、收藏及统一保留仍是后续能力，以上 Item 字段包含这些规划项。
- 默认数据目录的录屏历史同时扫描当前及明确的曾用品牌 `recordings` 目录，预览、播放与删除共用同一组允许来源；自定义数据目录只扫自身。视频保留原位置，不为改名复制一遍。列表只展示本轮安全扫描得到的文件；未出现在本轮的旧录屏索引，只有原路径明确不存在才清除，未扫描或读取不确定不视为丢失。
- 托盘启动完成后，后台把含已有记录或用户配置的旧 `workspace.json` 于事务内自动导入，首次实际访问也保留导入兜底。原文件保留作回退备份，成功后不再读写它。空目录与默认空配置不会因后台准备创建数据库。每张文档保留 512 KiB 上限，不再让整份工作区共享这一字节预算；现有记录数量、资源容量与保留限制继续生效。
- 默认品牌目录中，主库已迁移而登记图片仍留在曾用品牌目录时，后台按主库中的文件名补齐缺失图片；不覆盖新目录文件，不删除旧文件，不合并旧目录中另一份工作区。完成标记在全部检查与复制成功后写入，之后用户主动删除的图片不会被旧副本复活；来源冲突、权限或占位异常会阻止自动清理。自定义数据目录仅导入自己的旧 JSON，不探查品牌目录。
- 数据库使用静态链接 SQLite、WAL、外键及事务提交；锁竞争最多等待 300ms 后返回错误。托盘／待命首屏关键路径不等待数据库；消息循环运行后延迟启动后台迁移，再只读检查恢复条件，确有可恢复记录才启动恢复进程。已有数据库的只读访问可能由 SQLite 产生 WAL／SHM 辅助文件。
- Windows 读写与只读连接均规范化父目录并使用 SQLite 自带长路径 VFS。普通本地路径在数据库与最长旁文件名均未超限时移除多余扩展前缀，避免被引擎误归入 UNC 共享锁分支；Unicode 保留 UTF-16 往返。尾随点／空格、设备保留名等特殊目录拒绝打开，避免引擎归一化后串写到另一目录。深目录继续保留必需前缀；当前只验证单连接读写与只读访问，其并发 WAL 锁问题仍待底层修复，不计入本次并发保证。
- 外部删除／移动的截图或录屏在下次成功扫描后清除索引；贴图全部登记图片明确缺失、没有可恢复文字文档且无活动租约时自动清理记录。不确定的权限或占位错误继续保留，避免误清可恢复数据。

## 8. 进程与通信

- 主界面运行在现在设置窗口所在的辅助进程，单实例；不托管贴图窗口。
- 读：监视 `library\` 与 `pin-workspace\` 目录变更（`ReadDirectoryChangesW`），修订号变化才重读；贴图页可见时以 4 Hz 读取各贴图窗口的控制属性（锁定、穿透、忙碌），不可见时停止。
- 写：分组、标题、隐藏等走 `pin_workspace::apply(Action)`；需要贴图窗口执行的动作走现有单张控制通道，并扩展动作集：
  - 现有：Unlock、ClearClickThrough；
  - 新增：Lock、EnableClickThrough、Locate（闪烁置前）、MoveTo(x, y)（参数放窗口属性）、Close。
- 恢复已关闭贴图、从历史贴出：发给托盘，由托盘按现有路径启动贴图宿主（带记录 ID）；贴图宿主用会话租约防止同一记录被重复打开。
- 录屏预览不再在会话进程里开窗，只发“打开主界面 ▸ 历史 ▸ 录屏，选中 <文件>”。

## 12. M1 历史页（10-19 已进源码）

- 模型 `library.rs`：只读合并截图历史目录、`workspace.json` 的贴图记录（按租约分屏幕上／未打开／已关闭）、录屏目录顶层成片；贴图创建时间取编号里的纳秒时间戳（不随拖动变），旧编号退回 `updated_ms`。每处来源失败只记警告。本地时间用 `FileTimeToLocalFileTime` 换算（按当前时区偏移，历史上的夏令时差异不处理）。
- 界面 `main_history.rs`：筛选分段（带数量）、搜索、刷新；按本地日期分段的等高行照片墙（宽高比夹到 0.5–3，行高 150 DIP，末行不拉伸）；右侧 300 DIP 详情栏（窗口窄于 900 时隐藏，可开关）。缩略图最长 480×320，打开时按时间线顺序逐张后台解码、内存缓存，不写盘；录屏暂无预览（M3 首帧）。
