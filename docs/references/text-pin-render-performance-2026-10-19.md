# 文字贴图渲染提速（2026-10-19）

## 现象与原因

文字贴图（纯文字矢量文档）显示慢：首显、滚轮缩放、编辑时按键、拖动超出屏幕的长贴图都明显卡顿。

显示走两条 CPU 栅格化，都在 UI 线程的 render 里同步执行：

- Scene 1× 栅格（`raster::text` → `text_paint::paint`）：文字对象一变就整块重画，供导出与回退显示。
- 显示倍率重绘（`text_preview.rs` → `projected_text::paint`）：按“可见范围 × 当前倍率”重画，倍率、可见范围或对象一变就重做。

`projected_text::paint` 按 512×512 小块输出，每块都用 GDI 把**整段所有行**重画一遍（GDI 只裁剪不跳过），再逐像素单线程合成两次 `over`。60 行中英混排、700×3636 的文字贴图在 1.25× 下约 18 块，字形重复绘制 18 次；合成又对每个像素做浮点除法。

另外，可见范围（贴图窗口与虚拟桌面的交集）没有余量，长文字贴图通常比屏幕高，拖动时可见范围逐帧变化，显示预览就逐帧整块重绘。

## 改动

均要求与原输出逐字节一致，原逐像素／全行路径以测试开关保留作对照。

1. **只画相交行**（`text_layout.rs::draw_between`／`has_rows_between`，`projected_text.rs::layout_rows`）：每块把临时面四角经世界变换逆映射回文字局部坐标，只输出与该纵向范围相交的行；字形可伸出行框，前后各留两倍行高。块内无行且无底色时整块跳过。
2. **宽块**（`WIDE_CORE = 2048`）：块宽优先 2048，减少一行跨两列被画两遍；大描边使临时缓冲超 64 MiB 时退回 512 方块，能否绘制的判定不变。
3. **覆盖率查表**（`projected_text.rs::plain_table`、`text_paint.rs::plain_table`）：无底色、无描边的文字与水印，像素只由字形覆盖率决定；按 256 级覆盖率预先走一遍原合成函数，得到像素与“落在全透明目标上”的结果，目标非透明时仍走 `over_pixel`。零覆盖像素直接跳过，局部坐标只在序号／底色需要时才算。
4. **平移复用**（`text_preview.rs`）：同对象、同倍率与 DPI 的全密度预览只要覆盖本帧所需范围就直接复用；因平移失效时按可见范围四边各外扩半个可见尺寸重绘（不超过总像素预算、未被单边 16384 截断才用），首显、缩放、编辑仍只画可见部分。

没有做 GDI 多线程：`text_format::native_text_lease` 是进程级重入锁，按设计覆盖原生设备与字形整个生命周期。

## 验证

- 新增逐字节对照：`long_text_row_culling_matches_drawing_every_row_byte_for_byte`（40 行长文字 × 描边／底色／±旋转 × 0.6–2 倍）、`plain_text_coverage_table_matches_per_pixel_compositing_byte_for_byte`（文字／水印 × 三组颜色透明度 × 透明／半透明／不透明目标）、`text_paint` 查表对照；另有逆变换范围、宽块回退、平移复用与外扩范围测试。
- `cargo test --lib`：projected_text 10、text_ 537（唯一失败为既有 OCR 只读导航断言）、raster 45、scene 84、pin_text 205、watermark 30、serial 10 通过。
- 计时（`cargo test --lib text_pin_redraw_performance -- --ignored --nocapture`，60 行中英混排、700×3636，各取 5 次最小值，同机同条件换回原文件对照）：

| 项目 | 改前 | 改后 |
|---|---|---|
| Scene 1× 栅格（每次编辑） | 39.5ms | 25.4ms |
| 显示重绘 1.25×（850×4523） | 146.3ms | 36.8ms |
| 1.5×（1020×5427） | 161.8ms | 49.1ms |
| 1.875×（1275×6784） | 267.9ms | 69.9ms |
| 2.5×（1695×9040） | 488.9ms | 118.6ms |

  实际贴图只重绘可见部分，单次耗时按比例更小。改后 1.25× 的剩余构成约为：GDI 画字 15ms、取覆盖率 6ms，其余是分配与查表合成。

- 真实界面（首显、滚轮、拖动长贴图、输入）未验。

## 后续可选

- 编辑时只重绘改动行以下的部分（需要按行缓存字形覆盖率）。
- Scene 1× 栅格按需延后到导出时生成（触及核心 Scene 合同，收益约 25ms／次编辑）。
- 截图贴图缩放：vendor GPUI 圆角内容组里已有预乘双线性精灵着色器，可让底图直接用原图纹理在 GPU 上采样，省掉每档 CPU 重采样与几十 MB 纹理上传（需加“精确分数映射、不做精灵边缘 AA”的采样模式）。设计记录在 [贴图缩放延迟](pin-zoom-latency-2026-10-16.md) 的方向二。
