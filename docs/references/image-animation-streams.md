# 图片动画、条件系统来源与预算

图片查看器只保留一个工作线程。GIF、APNG 和 WebP 来源复用播放时钟与呈现桥；每幅交付帧携带像素、颜色事实和输出租约。旋转只重建显示副本，编辑、OCR、贴图及图片处理使用选中的完整帧，关闭来源后仍可消费该帧。

普通静态图和选中页也统一保留加载时的直alpha原色Arc及同次解码的元数据。编辑、OCR、贴图、处理和复制先捕获这份来源，再在工作线程生成独立像素副本，不从棋盘格显示图还原，也不按文件路径重新解码。文件长度与修改时间不能证明重新读取的是同一幅图；外部替换、删除文件或关闭解码来源不会改变已经交付的快照。等尺寸、等编码长度且恢复修改时间的PNG替换，以及删除来源后的像素与sidecar保留，已随快照专项回归通过。

目录去重按Windows完整UTF16序数忽略大小写比较，避免非ASCII大小写造成重复或有损代理字符误合并。枚举目录前注册可取消令牌，每项读取与元数据检查之间复核；取消返回错误，不沿目录失败降级单图成功。最多20,000项，标准排序仅在前后检查取消，单次排序及系统文件调用不能抢占。缩略LRU键改用完整文件身份，生成前后复核；身份不可用仍可生成本次缩略图，但不缓存。两项目录及一项同长度/修改时间替换缩略回归已通过，相关两项LRU回归也通过。

查看器在非100%缩放时也使用精确图像边界，不把分块原点向下取整或尺寸向上取整，网格与取色继续沿同一物理Viewport坐标。网格与颜色几何各两项回归通过；GPU采样和混合DPI实窗仍未验。

## APNG 与 ICC

APNG 来源限非交错的 8 位 RGB/RGBA。画布先按原编码 RGB 完成混合和处置，再由同一工作线程缓存的 ICC 变换生成完整 sRGB 交付图；不会每帧重新打开配置或创建变换。无配置时明确按 sRGB 显示；坏配置或转换失败保留完整原色画布并带出原因，取消不交付降级帧。已交付帧的颜色事实不会被后帧失败改写。

iCCP 独立校验 CRC、压缩方法和 4MiB 解压上限，元数据块总量限 8MiB。像素解码器忽略原 iCCP。重播核对配置内容与块位置；运行时到达冻结块位置就检查类型、长度和内容，不能把配置移除或改名后仍套用旧变换。非空 EXIF 动画暂不播放，沿静态入口归一方向并明确显示回退原因。

## 受控 WebP 来源

WebP 来源有界扫描 RIFF/VP8X、ANIM 和 ANMF，缓存帧目录，不收集整段像素或复制整份压缩输入。每帧冻结为唯一静态 RIFF Vec，完整工作区观察器与实际 codec 借用同一份字节，支持 VP8、VP8L 及 ALPH+VP8。打开来源时逐帧观察再释放，不预解主像素；播放时先取得输出租约，再冻结与观察当前帧。画布合成、上一帧矩形的背景处置及每轮重置由来源负责。背景采用 ANIM 的 BGRA 值；循环值表示总播放次数，0 为无限。原始毫秒延时保留，零延时按来源策略换算，播放器另有 10ms 下限。

混合当前使用 8 位原编码 RGB，完整画布再进行 ICC 转换；尚未实现线性光空间的 alpha 混合。它不代表完整颜色管理或所有合法 WebP 编码均已支持。规范中的线性混合建议、循环、背景和帧矩形语义见 [WebP 容器规范](https://developers.google.com/speed/webp/docs/riff_container#animation)。

输入限 256MiB、单帧原 ANMF 编码限 16MiB、帧目录限 20,000 项，ICC 限 4MiB、元数据限 8MiB。仅含已知像素块时虚拟 RIFF 比 ANMF 数据多14字节，单独核 Vec 实际 capacity。VP8L 观察覆盖四种变换、普通/简单 Huffman、cache/LZ 和 meta-Huffman 分组，压缩 ALPH 使用同一观察器；不再因合法复杂前导而拒绝。运行时仍以打开来源时公告的工作集为上限，同长度换尾若增大工作区也须拒绝。非空 EXIF 动画及线性光混合仍未扩展；未知ANMF子块只跳过无像素作用的payload，独立后继验证见下文。库内 CPU 解码期间无法强制中断，读取及调用前后检查取消，失败或取消后须 Restart。冻结码流及构造账本来源专项32项通过、1项原生默认忽略；未知块兼容另随后继6项通过，不混算批次。

ICC 指纹来自真正交给颜色管理器的同一份字节。普通交付只校验全局元数据和当前帧声明；构造、Restart、循环边界校验整个目录。未来帧被修改时，在交付该帧前拒绝，避免逐帧重扫全部目录的平方复杂度。

## 静态16位 RGB 与 ICC

统一入口对解码器交付的 RGB16／RGBA16 保留原 WORD 输入，在应用一次方向后进行受支持 RGB ICC 转换，最后才量化成直alpha BGRA8。输入与输出行使用 [BM_16b_RGB](https://learn.microsoft.com/en-us/windows/win32/api/icm/ne-icm-bmformat) 的 R/G/B 小端WORD和显式6W字节stride，与原8位BGR行分开；alpha不进入CMM，单独从16位量化。成功状态为 `ConvertedSrgb16`，仅附匹配当前像素的固定目标sRGB配置；无配置、坏配置、不支持或转换失败从完整原16位生成原色8位副本，取消不交付降级图。灰度ICC及浮点路径尚未作同等扩展，也不因此宣称高位深编辑或原精度往返。

后继L16／LA16补充原生解码、四分之一方向双缓冲和原生图+BGRA8的分阶段预算，取得真实capacity后再核；逐行可取消地生成单份BGRA8，灰度复制RGB，alpha独立最近整数量化，保留透明像素的直alpha隐藏颜色，不扩RGBA16。颜色事实仍沿原灰度来源：无配置保留原假定，坏或不支持ICC明确未应用，不给复制出的RGB套灰度配置或新增转换资格。四项真实PNG/八方向/ICC状态/容量与取消回归已通过，包含65536全值L16/LA16与旧转换的逐值对照。

文件入口传压缩Vec实际capacity，已知Vec的字节调用方可用 `decode_bytes_with_reservation`；借用切片仍只能报告len。元数据解析前先留16MiB逻辑工作区，不实际预分配。RGB16分配前核原源、ICC实际capacity、EXIF或错误文本驻留、分段视图/自有头与显式8KiB读缓冲、预计6P/8P；解码后改核原生Vec实际capacity。四分之一方向变换另核两份原生图峰值。颜色阶段不重复计已释放decoder视图，追加最终4P、两条各6W的WORD RGB行、配置与4MiB解析余量，每次新Vec分配再核实际capacity，各阶段限256MiB。系统codec/CMM私有缓存不受可见缓冲模型约束。

ICO／CUR内PNG、DIB沿 `decode_with_input_reservation` 继续传外层来源、虚拟单项Vec及目录实际容量；File来源不把整个文件len冒充内存驻留。图标仍由目录决定方向/热点，嵌入EXIF不再次旋转。WORD顺序、预算、alpha、失败/取消和导出资格等12项普通回归已随后继主target Dev构建全部通过。再后继显式运行原生WORD及RGB16 ICC/方向两项，均实际通过：linear灰128/65535经16位CMM后量化为sRGB约6，alpha独立保留、方向只应用一次。该低位样例与先降8位的0或约13分开验证，不推广为任意ICC或系统私有堆保证。

## 离线 SVG 查看与指定尺寸

统一文件/字节入口已注册SVG，在平台品牌和普通raster元数据探测前识别XML来源；集合头提示也先排除XML，合法前导注释不会被误认成BMFF。目录候选接纳 `.svg`，不接SVGZ，不把SVG作为多页来源。锁版直接依赖为 `resvg = { version = "=0.45.1", default-features = false }`，usvg、tiny-skia及roxmltree沿公开reexport；不引入浏览器或字体运行时。

内部查看器为已加载SVG显示“栅格尺寸”：输入精确宽高，按等比适应居中生成透明画布，原SVG文件不变。双输入的IME与Tab焦点由同一主题面板管理，确认绑定加载路径、代次和完整文件身份。重新栅格化沿现有单worker，读取同一打开句柄的冻结字节；分配前后都把旧原色、渲染Arc、缩略及元数据驻留量传入读入/XML/渲染/呈现各阶段。失败或取消保留原画布和视口，成功才替换并适应窗口；不把指定尺寸产物写进源文件缩略LRU。来源前后身份变化不发布新产物，身份检查仍不是文件内容CAS。

后端只从UTF8/XML树进入SVG转换，禁DTD、外部/data资源、系统字体加载及不受控效果；图片URI resolver两入口均显式拒绝。基本矢量、渐变、transform、简单clipPath和有界本地引用可进入渲染。XML结构与命名空间先行限制、引用展开、路径、图层/clip工作集和实际像素Vec分别在库调用或分配前核。继承paint或本地use会为实际图形派生渐变stop数组，转换前另按展开图形数×全部源stop数×fill/stroke两槽及缓存/派生两份计费，不依赖声明节点数量或Arc共享；超过128MiB逻辑工作区先拒绝。文字由转换前XML白名单和转换后的实际Node检查拒绝，不依赖树的文本摘要。XML解析、SVG转换与单次渲染无法中断，在前后检查取消，不发布取消后的像素。该工作区模型不是分配器硬上限。

指定尺寸为精确透明像素画布，按uniform meet居中；预乘RGBA在同一Vec内还原为直alpha BGRA8，透明像素RGB清零。颜色状态为 `RenderedSrgb`，导出可附目标sRGB；SVG没有原生像素网格或通道位深，来源尺寸、位深和方向保留未知，输出8位由实际渲染类型披露。首轮实际运行暴露合法树被文本摘要误拒：renderer 6过6失败、统一分派1过2失败；改为上述XML/实际节点防线后，新程序renderer 13项、统一分派3项、集合提示1项、尺寸输入2项及SVG worker2项全部通过。原资源/文字/预算拒收边界仍通过，首轮8个合法拒收失败已复验关闭；真实面板、GPU显示及导出交互尚未验收，不据此开放正式F10。

## 条件 AVIF／HEIF 预览

统一字节与文件入口先检查首个 `ftyp` 品牌表，表长限 4KiB，AVIF 品牌优先于通用 HEIF 品牌。系统来源嵌在统一解码模块内，沿用当前 Windows 依赖，不新增运行时。常规8位路径在原目录先选定图项，再重建只包含该独立图项的冻结 BMFF 输入；工作线程建立 MTA，由 [BitmapDecoder.CreateAsync](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.imaging.bitmapdecoder.createasync) 自动选择已安装的解码器，不强制把 AVIF 指定给 HEIF 解码器。组件缺失、编码不支持、坏图及线程上下文错误分别保留原因和 HRESULT，不把它们合并为成功或一律提示缺组件。

重建输入将唯一图项编号为1，保留其尺寸、编码配置和必要属性的原关联顺序与 essential 位，省去已核恒等 `irot`／`pasp`；码流按原 extent 顺序复制，不夹带其它图项或原 EXIF／XMP。`pixi` 的通道数与每通道位深必须符合已核码流；源未声明时仅为虚拟 AVIF 补出一致的 `pixi`。虚拟 AVIF 声明 `avif`／`mif1`／`miaf`，不照抄原能力品牌，依据[公开 AVIF 结构要求](https://aomediacodec.github.io/av1-avif/#image-item-boxes)检查最低必要属性；未据此宣称完成 MIAF 全文验收。系统必须返回唯一帧，只取帧0，并要求原始及 Oriented 尺寸均等于选中图项的已核显示尺寸。编码画布、位深和原图项ID来自该项，不能从相同尺寸的其它候选推测。

颜色属性保留来源声明，不凭空生成 nclx 或 ICC。实际 AV1 序列与 HEVC VUI 透出颜色字段、范围和采样模型：语法缺省值与显式容器 `nclx` 分开保存，属性面板也分行显示，不合并或借用其它图项的值。[MIAF 的公开决议](https://github.com/MPEGGroup/MIAF/issues/2)要求 RGB 显式声明颜色；现在仅实际矩阵确认 RGB 而缺关联 `colr` 时拒绝，YCC 4:4:4 不再被笼统拒绝。未识别模型保留未知，不反推或补默认颜色。每项允许一个 nclx 与一个 ICC 共存，重复 nclx 或多份 ICC 明确失败；ICC 只按所选图项关联借用。

像素请求为直通 alpha 的 BGRA8，显式忽略系统 EXIF 方向并[关闭系统颜色管理](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.imaging.colormanagementmode)，随后才做受支持 ICC 的一次转换。方向只沿选中图项的 `cdsc` 关联读取唯一 EXIF：前4字节大端偏移定位 TIFF，复用严格首IFD八方向解析；坏偏移、多份关联或非法方向均失败，不搜索备用头或猜 XMP。最终复制直接按该方向重排 BGRA，应用一次，无额外未定向 Vec。未声明方向按恒等处理。

系统持有者、原生像素数组和虚拟输入释放后，已识别 RGB／YCC 的8位来源可把对应 RGB ICC 交给统一 CMM，得到 sRGB 副本；alpha 不进入颜色变换。编码采样模型另存，ICC 管理摘要的 RGB 表示配置设备域。ICC 与 nclx 可共同描述颜色，不因 CP／TC 不同便判坏；矩阵仍用于平面到 RGB 的解码，参见[AOM 的 CICP 说明](https://github.com/AOMediaCodec/libavif/wiki/CICP)。仅成功转换的副本可另存匹配的固定 sRGB 配置；失败或不支持不授予原 ICC 保留资格，EXIF 白名单仍未提取。无 ICC 不走“无配置按 sRGB”的旧假定，而标记来源信号尚未映射。编辑、OCR、贴图及处理使用当前图项这份已交付快照。

无关联 ICC、有明确 nclx PQ／HLG 的 HEVC Main10 静态图项，在常规系统8位入口前尝试独立高精度分支。已核 hvcC 参数集和选中图项的有序 NAL 重组为 Annex B；复制按逻辑 extent 与64KiB块进行，可取消且不另建压缩来源副本。[MF HEVC 解码器](https://learn.microsoft.com/en-us/windows/win32/medfound/h-265---hevc-video-decoder)只枚举同步软件 HEVC→P010 变换，合格候选须唯一，只有已知且相同的CLSID可去重；不按友好名猜选，也不协商 NV12 或 RGB。当前限制10位4:2:0、48×48至4096×2304、容器与码流 CICP 一致、CP 1／9、TC 16／18、MC 1／9；缺组件、候选不唯一或其它未支持能力明确回退常规系统8位副本并附原因，坏数据、预算、取消及其它原生错误保留失败。

P010 在 MTA／MF 生命周期内读回到唯一紧行缓冲，随后释放变换、样本和运行时。要求单帧、正 stride、已核平面范围；物理尺寸只能是编码画布或码流显示尺寸，其余合法对齐扩展暂不支持。编码画布按已核 conformance origin 裁剪，已裁尺寸使用零原点；若系统报告[显示孔径](https://learn.microsoft.com/en-us/windows/win32/medfound/mf-mt-minimum-display-aperture-attribute)，它必须与同一次裁剪精确一致。借用采样器按[P010小端WORD与平面布局](https://learn.microsoft.com/en-us/windows/win32/medfound/10-bit-and-16-bit-yuv-video-formats)读取10位有效值，应用一次全／有限范围和 YCC 矩阵，色度用最近2×2样本，返回编码域 RGB16。不会把 WinRT 的 RGBA16 格式名当作原始 PQ／HLG 精度或颜色域证明。

RGB16 回调直接生成最终 BGRA8，不建立整帧中间 RGBA16。PQ 使用绝对亮度 EOTF；HLG 使用逆 OETF 和1000nit参考、黑0、gamma1.2的共同场景亮度增益，709原色的HLG是本应用扩展。解传递依据[BT.2100](https://www.itu.int/dms_pubrec/itu-r/rec/bt/R-REC-BT.2100-3-202502-I!!PDF-E.pdf)，显示肩部则是本应用固定策略：≤75nit保留，之上 `75+25*(Y-75)/(Y-50)` 渐近100nit；按共同亮度缩放，再由2020／709线性原色转709、裁色域并施加 sRGB OETF。它不代表标准HDR tone mapping或显示器校准。EXIF八方向只在写入最终位置时应用一次，P010来源不含alpha、输出不透明。成功整帧才设置 `HdrMappedSrgb`，颜色保留选项附固定目标sRGB配置；原位深、方向、CICP和图项身份继续作为来源事实显示，编辑及另存明确使用8位SDR副本。

原生阶段在分配前核原源容量、目录实际容量、Annex B实际容量及其MF输入副本、输入对齐余量、有界激活数组、SPS picture模型、输出样本上界、紧行P010与最终4P；读回容量再核。输入与输出分别遵守stream info的对齐要求；后继源将变量长度输入的最小buffer容量与实际Annex B有效长度分开，最小容量分配前及Lock实际容量取得后重核同一账本，固定样本不等长／原地输入仍拒。MF可能持有输入sample，本地引用释放后其容量仍贯穿输出及读回计费。映射阶段仅保留原源、目录、实际P010容量与最终BGRA容量，两阶段各限256MiB，另受调用者最终输出预算约束。COM／MF、激活对象、样本与两种缓冲锁均通过拥有者释放；单次系统调用耗时与codec私有堆仍无法由取消或可见缓冲模型约束。后继主target Dev构建已实际通过HDR/接线11、P010八项、HEVC纯helper五项、真实10位主码流头两项、平台颜色八项及系统分派两项，共36项普通回归；与WORD十二项同批补验共48项。它们不调用原生MFT，不继承到后继输入容量修正，高位深/HDR原生仍未验收。AVIF高精度、含ICC的HDR、其它采样／位深及固定策略的真实像素验收仍未完成，不把纯数值或主码流头检查当作 F09 完成。

首／前／后／尾导航来自原容器的独立图项目录：原主图置首，其余非隐藏图项保持原目录顺序，隐藏图项仍须完整预检。属性中的原ID与主图标志只随实际交付项显示。未解码项不伪造像素尺寸，后续项失败仍可沿已有目录恢复，已交付快照不重新读成文件首图。目录列表接纳 AVIF、HEIC／HEIF 及其序列扩展名，实际格式仍由文件头判定，序列能力尚未提供。

输出限调用者的最终 BGRA 字节预算；裁前编码画布独立核32MP和单边65,535像素，不能因显示裁剪较小而省略。来源实际 capacity 先留16MiB的有界预检工作区，防止目录或EXIF在最终核算前越限；不会实际预分配这份余量。重建前按精确长度、重建后按实际 capacity 合计原源、单图虚拟 Vec 和 COM 流副本，另计目录实际容量、元数据、选中项逻辑码流与按编码画布／位深／DPB计算的 picture 模型，以及系统目标与两份BGRA输出，合计限256MiB。全部图项逻辑长度另有总量上限，重复 extent 不能靠物理源较小绕过。8位 picture 按4字节每像素、高位深按8字节每像素覆盖；系统目标格式未知时按8字节每像素预留。系统 codec 私有分配仍不受公开接口约束，异步 `get()` 也不能由取消标志强制打断；调用前后、重建复制和像素复制检查取消。当前仍缺原生验收，不视为 F09 完成。

后续 ICC 阶段单独核原源容量、仍驻留的目录 Vec、输入图实际 capacity、新4P像素、一对共6W字节的BGR行缓冲、配置与4MiB摘要工作区，总量同样限256MiB；解析配置或进入 CMM 前即检查。两阶段峰值不直接相加，也不能漏掉调用方尚持有的原源。CMM 私有缓存不受这个可见缓冲模型约束。

系统调用前还限制静态 BMFF 子集：只接受有完整图项、位置和配置关联的独立 `av01`／`hvc1` 图项，固定层级检查目录与本文件 `mdat` 范围；所有 `ispe` 声明先核尺寸及调用者预算。目录与元数据分别限数量和8MiB。序列轨道、派生图、外部数据、未知结构及未证明的显示变换暂不进入系统解码。位置表保留每个图项有序的 extent，码流预检逐图项绑定其唯一尺寸与配置，不复制整份压缩图项，也不能只检查主图或全局第一个配置。

AV1 检查实际图项的 OBU 至逻辑末尾，要求唯一实际 Sequence Header、单个 Frame 及 av1C 字段一致。当前支持单层 reduced still，检查完整序列配置与帧显示尺寸，拒后置头切换、分层、分离帧结构、超分辨率和胶片颗粒等未支持结构；参考槽可别名同一 picture，此模型按一个不同 picture 计入。HEVC 遍历 hvcC 与实际图项全部长度前缀 NAL，检查 VPS／SPS／PPS 的ID链、配置与载荷参数集一致性、裁前尺寸、conformance crop、位深及 DPB；实际只接单层单 IDR，直接 RPS 有界解析，预测／长期参照及复杂扩展暂不支持。所有非主图项也须通过检查。头预检不验证完整熵编码，也不保证系统实现只按模型分配。

真实白色 AVIF 可确认编码画布1×1／8位；HEIC 可确认裁前256×128、显示250×128／8位。另加入上游MIT许可的Main10裁剪样本，原始字节2597B，来源标明10位4:2:0、256×128→248×122、起点(6,4)，其实际主码流头回归已随上述普通批通过；它的传递函数为sRGB、矩阵为601，当前HDR后端在MF前拒绝这个颜色组合，不能据此宣称已跑原生P010。另有200×200的10位PQ样本，实际是AV1 4:4:4，其主码流头用例也已通过；原文件包含HDR gain map辅助项，完整容器当前仍明确不支持，也不能交HEVC后端，不删辅助项或据主图头宣称HDR映射通过。来源、许可及未验范围见[样本说明](../../tests/data/image_platform/README.md)。五帧 AVIF 仍用于明确拒绝序列的能力边界，不据此宣称已支持动画。

两项静态原生检查默认忽略，但后继已显式运行：HEIC真实解出250×128单图，8位、裁窗与全opaque alpha门通过，未验证RGB金值；AVIF白色样本实际失败于Native HRESULT 0x80070057，没有走“条件能力不可用”分支。后继测试构建的阶段记录与原始/冻结对照均已实际运行：原始305B与冻结289B都成功请求像素，却在异步像素交付完成处返回相同Native错误，两份结果完整打印后才强失败；目前没有重封特异的失败证据。不能把该失败改称组件不可用。

再后继测试诊断对照BGRA/直alpha、BGRA/忽略alpha、RGBA/直alpha及系统原生四字节参数，并打印系统原生格式，现已实际运行。原始与冻结共8项全部在像素交付完成阶段返回同一Native错误；原生默认均为Bgra8/Ignore，没有任何case因alpha断言失败。由此也不能归因为仅Straight转换问题；尺寸、profile或采样的具体限制仍未确证，生产参数及错误分类未改。每份结果保留实际请求alpha；[Ignore模式按不透明解释且允许存储alpha为0](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.imaging.bitmapalphamode)，该case只核四字节和白色RGB、原样打印第四字节，Straight及本不透明样本的Premultiplied仍硬核255。每项Native错误仍须强失败，不以参数对照替换原生产Straight验收。

同时补入官方25KiB的常规尺寸AVIF基线，来源见[样本说明](../../tests/data/image_platform/README.md)。新增普通预检将单图目录、768×512和声明8位420绑定到实际码流头，再对冻结输入重新预检，已实际通过。另一默认忽略用例已显式运行通过：原始25430B与冻结25414B均解出768×512、每幅1572864B，固定BGRA直alpha请求返回opaque、空间非均一的RGB，整幅BGRA逐字节一致。2MiB是每幅输出上限，WinRT数组、自有副本和两份结果会共存，不是整个探针驻留上限；codec私有堆仍无保证。该检查不提供独立RGB金值，也不消除1×1样本的真实失败。

Main10组件测试使用该原样本的[重建哈希参考](https://github.com/libheif-org/heif-testcorpus/blob/master/corpus/hevc-conformance-window/README.md)，不猜像素或伪改成PQ。按[H.265附录D的decoded picture hash](https://www.itu.int/rec/dologin_pub.asp?id=T-REC-H.265-201304-S%21%21PDF-E&lang=e&type=items)，P010先取小端WORD右移6位、拆开UV，各平面按栅格顺序将10位样本的低字节、高字节送MD5，排除stride。哈希覆盖完整256×128编码画布；系统只交裁后图时不能用它验像素，也不能以尺寸或非零值代替。

对应后继源码已通过主target Dev测试构建，新增普通资格门1项实际通过。生产入口保留原HDR颜色门，已核`OutputColor`贯穿同一输入、输出与stream-change协商；只有测试入口接受该SDR样本的确切CICP与几何，复用同一MFT、Annex B和P010读回。显式原生测试要求完整256×128、stride512、98304B再按三平面MD5硬验，裁后、缺组件及Unsupported均保留失败。实际运行在激活解码器前读取候选的`MFT_TRANSFORM_CLSID_Attribute`时返回`MF_E_ATTRIBUTENOTFOUND`（0xC00D36E6），保持Native硬失败；没有得到P010或MD5，不能授予像素通过。后继有界候选观测也已实际运行，确认只有一个合格同步软件activation，CLSID确实缺失。

再后继唯一候选的兼容修正已通过主target Dev测试构建，1项新身份合同普通回归实际通过：只把CLSID属性不存在记为未知ID，其它错误及取消原样传播；单一合格activation可直接激活，多个候选只有双方已知且相同的CLSID才可去重。未知＋未知、已知＋未知和不同已知ID均拒绝歧义，不按友好名称猜选，也不跳过未知候选。官方[属性合同](https://learn.microsoft.com/en-us/windows/win32/medfound/mft-transform-clsid-attribute)称枚举对象应带CLSID；这里针对已观测的缺失做兼容，依据[枚举／激活合同](https://learn.microsoft.com/en-us/windows/win32/api/mfapi/nf-mfapi-mftenumex)直接使用唯一activation，不声称规范上普遍可缺该属性。

之后原生项又实际失败于输入缓冲门：已激活async=0、输入／输出各1流并协商coded P010，但输入flags=0x3、最小buffer49152B、alignment／lookahead／latency均0，而Annex实际2313B。旧门把最小容量大于有效长度误判为未支持。后继依[输入容量](https://learn.microsoft.com/en-us/windows/win32/api/mftransform/ns-mftransform-mft_input_stream_info)与[有效长度](https://learn.microsoft.com/en-us/windows/win32/api/mfobjects/nf-mfobjects-imfmediabuffer-setcurrentlength)合同修为容量取max、有效长度仍2313；分配前按请求容量、Lock后复制前按实际容量核同一账本，MF输入容量持续计入输出及读回。固定样本不等长、inplace及alignment门保留。主target Dev测试构建后，新增容量精确边界／溢出1项与受影响alignment/status、原可见容量各1项，共3项普通回归实际通过、0 ignored，旧绿不重复。

同一新测试程序已显式运行原生MD5项通过：实际完整P010为256×128、stride512、98304B，孔径为(6,4,248,122)；Y=`ac4be59f1a01fbafb78b19768d00c559`、Cb=`ba36c243797e5a430c864d8d886abcf7`、Cr=`e5ac9a5cdf5dbeb2b810fe3d655b6958`全部精确匹配独立SEI参考。此前CLSID及输入最小容量失败均经对应修复后闭合，没有把缺组件、Unsupported或裁后图改成条件成功。这只证明该SDR Main10样本的MFT／P010完整编码画布读回与CNG校验，不代表PQ／HLG映射或新的SDR生产入口。

BCrypt对象查询与实际容量各限64KiB，三平面串行复用512B行缓冲，原生句柄先于对象缓冲与provider释放；NTSTATUS单独记录，不当HRESULT。容量模型只覆盖可见缓冲，codec与CNG私有堆未保证。本次SDR检查通过不扩大生产HDR资格；真正HDR仍缺匹配受支持子集及独立像素参考的受控样本。当前Dev运行版已含CLSID唯一候选兼容及输入最小容量修正；普通Dev三程序已实际更新到tray-run，托盘与同路径待命已启动。

普通完整图在非原尺寸沿用线性过滤，但 Windows atlas 图块没有 halo，sampler 的 wrap 只以整张 atlas 为界，不能隔离邻图。当前 polychrome atlas 与渲染目标都是 BGRA8_UNORM、atlas 只有一个 mip，实际 sampler 为线性且不使用各向异性。后继只在普通彩色 fragment 的 linear 分支，将插值后的 UV 钳到本图块首末 texel 中心再执行原 Sample；1×1 的两端相等。图内映射、最近邻、grouped 预乘采样、几何覆盖率、opacity 与灰度保持原逻辑，未替换顶点映射或更改 ABI。

原2×1放大失败仍是此前构建的真实结果；边界钳制目前仅完成源码与独立静审，尚未授予修复通过。本次Dev构建期间修改过HLSL，尚不能保证运行候选已拾取本修正。新增小PNG专项已接线，检查zoom8的2×1／1×1均色图四边、整数／分数物理位置及4×1色条内部混色；每组全3×3逐点容差1，内部混色另须明显区别于nearest。它复用既有自有窗口、framebuffer读回与真实worker退出门，Edge路由不生成36MP来源，尚无后继测试构建与显式实跑回执。像素期望必须位于几何覆盖完整的内域，不把quad_sdf合法的外缘覆盖误认成采样污染。透明源图内部的straight-alpha插值、跨瓦片无缝过滤、多DPI与DWM合成不在这项证明范围。

超过16384单边的完整图仍使用4096无halo核心块；逐块边缘延拓不能证明跨块双线性连续。只补一个源像素邻接边也不足以保证所有缩小比例避开quad边缘AA，此后继未纳入当前人工测试候选。

## 源文件重命名与回收站

查看器内的主题面板固定本次源路径、加载时身份和代次：重命名输入完整叶名，改扩展名不转换图片字节；回收站另行确认，初始焦点为取消。模态输入优先于最近列表、GIF控制和查看器快捷键，组合输入不被Enter/Esc抢先提交。处理期间禁用名称框、聚焦取消并锁定切图；Esc请求取消后等待实际回执。已完成的操作不会被迟到取消改报为未发生，关闭窗口只取消未提交的后台工作。

重命名核已打开源句柄身份，并把目标锚定已核父目录句柄；[FileRenameInfo的ReplaceIfExists=false](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_rename_info)负责原子拒绝目标重名。路径、设备名、尾点/空格及UTF16长度先检查，不经先删目标或路径式替换。成功后保留冻结原色、选中帧/页、旋转和视口，在后台重扫目录并更新当前路径、缩略代次及窗口内最近列表；复制文件引用也会重核加载身份，不能把外部替换的文件当作已交付来源。

回收操作在专用STA中向IFileOperation提交一个源项，依赖[FOFX_RECYCLEONDELETE与ADDUNDORECORD](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags)的Shell合同，不提供永久删除降级。PreDelete再核本地资格、完整身份、取消及回收标志；实际PostDelete回收项与最终aborted/源路径观察分别回报，不把排队或Perform成功当作回收完成。操作回调与随后Shell提交仍不是文件系统CAS。本机固定、可移动及内存磁盘沿能力返回结果，网络/设备路径不进入这条操作；文件系统身份或回收能力不可用时明确失败。成功后从最近列表移除该源，转到邻图或清空当前来源；失败保留冻结预览和错误。九项纯策略/回执及两项最近列表回归已通过，三项真实句柄/回收测试按设计忽略；真实文件操作和界面尚未验收。

## 工作集与验收

设画布像素为 P，最大局部帧像素为 F，最大帧编码大小为 C，来源 ICC 大小为 N，画布宽为 W。默认最多四个交付租约，旧帧租约跨 Restart 仍占名额。预算先于整幅像素与颜色变换分配检查。

普通File读入按同一已打开句柄的长度一次精确分配，取得实际capacity后再次核源缓冲与64KiB分片工作区。提前EOF或多出尾字节明确报来源变化，不通过128→256MiB扩容造成新旧整份压缩Vec并存。显式SVG尺寸入口另在分配前核8MiB源上限及宿主驻留量。六项输入预算、partial/EOF/增长、Interrupted及取消优先回归已通过；它不把读取过程声称为外部内容原子快照。

邻图解码新增显式宿主驻留预算入口，目前只接受PNG（含16位）、BMP及8位JPEG，不改变普通前台入口的格式范围。宿主驻留量贯穿输入Vec扩容的旧/新共存、原生解码、四分之一方向变换、RGBA和CMM阶段；每阶段检查预计分配与取得后的实际capacity。锁版JPEG还核有界输入私有副本、按MCU及采样因子补齐的全图i16系数、行/上采样工作区和固定余量，支持渐进及受控CMYK；未证明的结构拒绝预取。八项定向回归已通过，包含真实PNG8/16、BMP、渐进/CMYK/方向JPEG和容量边界。此模型不覆盖系统私有堆，也不能推广为所有前台格式的宿主驻留保证。

- GIF：解码器的ICC/XMP各限逻辑B=512KiB，摊销增长时按旧/新块及另一类元数据合计5B，另留256KiB读入/LZW暂存；首次读写前检查此固定构造峰值。暂停驻留只计4B+256KiB，已释放的增长旧块不计。canvas、索引、Previous和输出分别核实际capacity，较小后帧允许复用已获画布名额。
- APNG：普通画布为48P，任一边超过16,384时为52P，另加32MiB固定预留、活动ICC的3N和两条BGR行的6W。固定预留包含PNG行与解压暂存、原元数据块及其副本和8MiB缩略缓存；canvas、局部解码、Previous和交付帧另核实际capacity。
- WebP：原canvas实际capacity与四份租约名额构成基础，普通呈现另计20P，超长边24P；再加8MiB缩略缓存、8MiB元数据池、目录实际容量、固定ICC过渡预留3N及6W行。每帧只加一份冻结RIFF实际capacity与128KiB读入余量，以及constructor、native+decode_extra、256KiB观察余量+max(4F,1024)三相位的最大值；不再重复计3C或18MiB粗预留。manager文案、L份交付副本、格式化暂存与UI两份文案由(L+4)份历史最大warning容量约束在元数据池内，首次颜色降级不得抬高来源公告预算。scan另按缓存/元数据/IO固定量加目录、ICC实际容量核构造阶段，扩容前后均核旧新共存；扫描时尚未分配未来像素，不把两阶段相加，最后公告取构造与运行峰值较大者。
- 3N 覆盖失败降级时原 ICC Arc、复制 Vec 和新 Arc 短时共存；长期降级只保留一份适用的源配置。系统 CMM 内部缓存、GPU 缓存及调用者已经持有的压缩输入不在可见缓冲预算中。
