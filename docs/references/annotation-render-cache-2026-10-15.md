# 大量标注的渲染缓存（2026-10-15）

## 问题

用户反馈：铅笔来回涂抹几十笔后，继续画、悬停、拖动都很卡。原因是每帧把全部标注层重新做成 GPU 路径：

- 一笔 400 点的来回涂抹，并集网格约 7 千顶点、9 千三角形，加解析 AA 边缘后约 5.8 万路径顶点。40 笔约 36 万三角形、230 万路径顶点。
- 单是 `vector_paint::vector_path` 就要约 61ms／帧（dev 配置为 opt-level 2）。GPUI 还要把路径顶点再复制两份（`paths` 数组与 paint 操作列表），每个顶点转成约 100 字节上传。
- 每条矢量笔迹各自一个 `coverage_union` 批次，各做一次 MSAA 清空、resolve 与合成。
- GPUI 在最后一次输入后 1 秒内，每个 vsync 都重复 Present 同一 Scene。所以只是移动鼠标，也会按上述成本反复绘制。

## 做法

### GPUI 保留层（`vendor/gpui`，仅 Windows）

`Window::paint_retained_layer(layer, key, mode, bounds, paint)` 把内容画进一张跨帧保留的纹理，之后只做合成：

- `Rebuild`：清空后绘制；`Append { base }`：在已登记为 `base` 的内容上追加；`Reuse`：不执行 paint，直接合成。
- renderer 侧按 `Arc<RetainedLayer>` 身份保存纹理（`RetainedEntry`）。整组画完才登记内容键并写回 `RetainedLayer::ready_key()`；中途失败键为 0，不能复用。
- 每次 paint 的请求带唯一 `id`。同一 Scene 被重复 Present 时按 `id` 直接复用并跳过组内原语，`Append` 不会叠画两次。
- 帧末释放本帧未使用的纹理；resize、设备恢复时全部失效并清零。内容意外不可用（如父组 ROI 变化）时放弃该帧，并投递 `WM_GPUI_FORCE_UPDATE_WINDOW` 强制整帧重绘，让上层改为重建，不会一直卡在旧帧。
- 实现复用现有圆角内容组：组内用组混合状态，结束时按整数 ROI 原样拷贝（轮廓取 ROI，本身不裁边）。

同一补丁里，圆角组内路径中间面按 2 的幂分档（不超过组本身）分配，后续较小的批次直接复用。重建几十笔时不再逐笔创建 MSAA 纹理；预算不足时退回精确尺寸。

### 画布分段（`vector_paint::RetainedAnnotations`，`capture_canvas.rs`）

- 每层的绘制身份 = Scene 层（`scene::same_layer`，按 Arc 身份比较）+ 文字／水印层实际使用的预览图地址与范围。
- 投影参数：画布原点、缩放、DPI、画布与视口尺寸、贴图外层内容组范围。参数变化时两张纹理都作废，当帧整体重建；连续缩放／平移期间每帧都重建。
- 与上一帧比较出本帧变化的区间 `[prefix, n - suffix)`，分成三段：
  - 下层纹理：缓存的层列表仍是当前的前缀就复用；稳定前缀变长时用 `Append` 只追加新层。
  - 实时层：草稿、正在拖动的对象等，逐帧直接绘制。
  - 上层纹理：变化区之上的稳定后缀（例如拖动中间一笔时它上面的全部笔迹）。
- 提交一笔：当帧下层复用、新层实时画，下一帧把这一层追加进下层纹理。撤销：下层只能按剩余层重建一次。
- 预乘 source-over 满足结合律，三段依次合成与逐层直接绘制一致，差异只有 8 位中间纹理的量化（±1）。组内着色器约定沿用圆角组，与贴图呈现路径相同。
- `RetainedAnnotations::disabled` 只给性能对照专项用。

内存：每张纹理为画布可见区域的 RGBA8（4480×1440 约 24.6 MiB），最多下层、上层两张（10-16 起静止时也是两张：最上一层单独一张），不用时帧末释放。

### 拖动时平移网格（`scene.rs::Scene::updated_live`，2026-10-16）

- 编辑器 `live_object_indices()` 列出正在拖动／变换的已提交对象（`Gesture::Object`、`Gesture::Group`），`capture_view::prepared_scene` 把它传给 Scene。
- 列出的对象若与“基准”只差所有点同一平移量（tool、style、文字、旋转、填充几何都相同，逐点容许 f32 加法舍入），就把基准的 `VectorMesh` 顶点整体平移，索引、外沿、法线照搬，跳过 lyon 细分与三角形并集。只用于 `Layer::Vector`；正片叠底荧光笔的画刷块随位置变化，仍完整重建。
- 基准是拖动前一帧按完整质量生成的那一层（`MoveBase`），整个拖动期间都从它平移，不逐帧累积舍入；草稿网格和失败层不能作基准。
- 导出合同：1× 合成（`try_apply`）只读 `path`／`segments`，平移帧也按当前标注精确生成这两项，所以拖动中 1× 输出就与全新 Scene 逐像素一致。放大导出和显示快照会读网格，所以平移网格只活在手势里：手势结束后的那次更新不再列出该对象，按完整质量重建（与全新 Scene 网格逐位相同）；取消拖动回到基准位置时直接沿用基准层。前缀复用与“上层原样沿用”都排除了平移层。
- 方向键微调每次都是一次提交，不属于手势，仍完整重建（每次一笔的成本）。松手那一次也完整重建这一笔（10-16 起不做 CPU 并集，真实一笔约 2–6ms）。

### 草稿分块细分（`vector_mesh.rs::build_draft_pieces`，2026-10-16）

- 正在画的笔迹每 32 个跨度细分成一块，各自带圆头；下一帧与上一帧跨度前缀相同的块直接沿用，只重新细分变化处之后的块，再拼成一个网格（索引按块偏移）。缓存存在 Scene 的 `draft_pieces`，只在相邻两帧草稿之间传递，按跨度内容判定，不靠下标身份。
- 接缝：两个圆头的并集正是圆角连接覆盖的圆盘，几何覆盖与整笔一致；接缝处多出的内部边在另一块的满覆盖之内，GPU `coverage_union` 取 MAX，不留缝也不加深（与草稿自交处同一机制）。测试以 1/4 像素采样比较整笔与分块网格的覆盖，差异低于 0.05%。
- 虚线（相位依赖整条路径）、箭头、带填充轮廓的路径仍整笔细分。提交后由 `build_display` 整笔重建（见下节）。
- `pencil::fit` 的改动只在尾部，400 点生长过程中平均每帧重新细分不到 2.5 块。

### 按真实采样密度复查：几何量才是根因（2026-10-16）

用户反馈前述缓存之后绘制中、画完后、在笔迹上拖马赛克仍卡。前面的基准和 pencil-perf 都用每点相隔约 20 px 的稀疏往返，而真实鼠标（1000Hz、`PencilSamples` 补回合并样本）相邻只有 1–2 px。按真实密度重测（`scene.rs::hand_drawn_pencil_cost`、`vector_mesh.rs::hand_stroke_tolerance_cost`，一笔约 1.5 秒、1400 个整数样本）：

| 环节 | 旧值 |
|---|---|
| `pencil::fit` | 1.3ms，312 段三次曲线，展平 1073 段 |
| 草稿网格（不并集） | 3–5.6ms，5.2 千顶点，GPU 路径顶点 4.7 万 |
| 提交时三角形并集 | 41–79ms（Scene 内整笔提交 106ms），9 千顶点、1.35 万三角形，GPU 路径顶点 6.8 万 |

GPU 本身不是瓶颈，瓶颈在 CPU 端几何：每次抬笔卡约 0.1 秒；一笔 6.8 万路径顶点，20 笔 136 万，任何整层重画（开始拖动最上面的马赛克、撤销、缩放）都要全量重传。常见做法是按约 0.25 DIP 展平并缓存几何，也不做逐笔 CPU 并集。

改动：

- **提交不再做 CPU 并集**（`VectorMesh::build_display`）：画布显示走 GPU `coverage_union` 的 MAX 覆盖率，自交、折叠处不加深，与草稿同一画法。并集只服务外边界扫描的 CPU 覆盖率（放大导出、贴图取色），由 `VectorMesh::exact()` 首次读取时按原路径惰性计算并缓存在网格里；平移网格（`translated`）换成平移后路径的惰性来源。正片叠底荧光笔的画刷路径不走 MAX 合并，仍在 Scene 里直接并集。
- **细分容差 0.01→0.03 px**（`STROKE_TOLERANCE`）：与 `VectorPath::flattened` 一致，铅笔拟合误差预算本就为 0.03 px 细分留了余量。同一笔顶点 −37%，以 1/4 像素栅格比较覆盖差异 0.15%。8× 放大贴图时偏差 0.24 屏幕像素。
- **静止时最上一层单独一张保留纹理**（`RetainedAnnotations::plan_with`）：下层纹理只放 `[0, n-1)`。拖动／微调刚放下的对象、撤销最后一步时下层纹理仍然有效，不再整层重画；代价是开始画下一笔时把原最上一层追加进下层、提交后单独建一次上层，各只画一层。拖动中间层仍是下层、上层各建一次。常驻纹理由一张变两张（4480×1440 各约 24.6 MiB）。
- **编辑模式命中测试先用样本折线粗判**（`Annotation::hit`）：拟合曲线与样本折线双向相距不超过约 1.25 px，距离明显大于／小于“容差 + 半线宽”2 px 以上直接给结论，只有贴边时才重新拟合整笔。原先悬停每次移动要对鼠标下每个外框重叠的笔迹各做一次 `pencil::fit`（真实一笔约 1.3ms）。
- `VectorPath::bounds` 不再为每个跨度分配临时数组；下层合成的每个 128 px 分块都会对每笔调用它。

## 局限与后续

- 拖动中间某一笔的首帧仍要把下层、上层各重画一次（40 笔约 150ms）。
- 开始拖马赛克的前两帧在 CPU 上合成下层（首帧按原范围、次帧分块建缓存），20 笔约 19ms。

- 草稿的 `pencil::fit` 与 GPU 路径准备（`FramePaths`）仍逐帧处理整笔：3000 点时拟合约 1.3ms，路径准备随网格顶点线性增长。要继续压，需让拟合只重算尾部窗口，并把草稿已稳定的块提前追加进下层纹理。
- 连续缩放／平移图片期间每帧都整体重建，成本与旧逐帧绘制相当。
- 撤销／删除下层对象后会整体重建一次（一帧旧成本）；撤销最上一层已直接复用。
