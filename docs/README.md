## 新贡献者阅读顺序

1. 阅读[术语](glossary.md)和[架构](architecture.md)，建立核心对象与模块边界的共同认识。
2. 按[开发](development.md)准备环境，并结合[行为清单](behavior.md)确认当前行为。
3. 查阅[当前状态](status.md)和[开发路线](roadmap.md)，确认已有实现、待验证项与改动依赖。
4. 按任务查找[专题](references)、[研究](research)和[原型](design)，阅读相关源码后实施改动与定向验证。
5. 按[参与贡献](../CONTRIBUTING.md)准备提交，说明改后行为、验证范围与未验项。

## 维护方式

行为变化更新行为清单，路线变化更新开发路线；尚未完成或待验证的工作更新当前状态。设计理由与验证结论写入所属专题，实验比较写入研究记录；每个概念在所属文档中维护定义，其它页面通过链接引用。

专题和原型按任务查阅，避免将历史计划或某次测试结果直接当作当前完成状态。
